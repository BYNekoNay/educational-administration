## 完善前端报错提示：Uncaught(in promise) 不再外泄（2026-07-14 17:xx）
- **现象**：管理后台课程管理保存时，若后端返回业务异常（如 `课程价格必须大于0`），控制台报 `Uncaught (in promise) Error: 课程价格必须大于0`，界面无任何提示。
- **根因**：`CourseList.vue` 的 `handleSave` 用 `try{ } finally{ }` **无 catch**，reject 的 promise 变为 unhandled rejection 泄漏到控制台；`request.ts` 对 `code!==0` 的拦截分支只 `Promise.reject(new Error(message))` 不弹窗。
- **修复**：
  - `admin-web/src/views/edu/CourseList.vue`：`import { showError } from '@/utils/error'`；`handleSave` 改为 `try/catch/finally`，catch 调 `showError(e,'保存失败')`；`handleDelete` 同样加 catch（保留 cancel 分支不提示）。
  - **新增全局兜底** `admin-web/src/utils/error-guard.ts`：`installGlobalErrorGuard()` 监听 `unhandledrejection`，对**非 axios/非 HTTP** 的拒绝（即业务 `new Error(message)`）调 `showError` 展示，并 `event.preventDefault()` 抑制控制台默认 Uncaught 打印；`main.ts` 已调用安装。HTTP 错误仍由 `request.ts` 拦截器单独提示，跳过以免重复。
- **验证**：`npm run build` 成功（仅 chunk>500kB 警告）。真实 API 复测：`POST /api/edu/courses` 传 `price:0` → 后端返回 `{"code":400,"message":"课程价格必须大于0"}`，前端 `showError` 提取 `e.message` 直显该文案。
- **规范（前端错误处理）**：admin-web 中任何 `await api.xxx()` 必须包在 `try/catch` 且 catch 调 `showError`（不要裸 `try/finally`）；已统一工具 `@/utils/error` 的 `getErrorMessage` 会优先取 `response.data.message` → 否则 HTTP 状态中文 → 否则 `e.message`。全局 `error-guard` 仅作最后兜底，不应替代局部 catch。

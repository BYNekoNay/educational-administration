## 18:02 前端菜单权限实际生效
- **现象**：即使角色只分配了部分权限，使用该角色的用户登录后仍能看到所有菜单（权限未实际过滤）。
- **根因分析（3 个关联缺陷）**：
  1. **登录竞态**：`setLogin()` 中 `fetchPermissions()` 未 `await`，路由守卫在权限加载完成前已触发 → 非 SUPER_ADMIN 必然因空 Set 被拦截。
  2. **API 权限不足**：`fetchPermissions()` 对非 SUPER_ADMIN 调用 `roleApi.list()`，该接口被 `@RequireRole({"SUPER_ADMIN"})` 保护 → 403 → 回退到 `['menu:dashboard']`。
  3. **LoginResponse 不返回权限**：前端必须额外 API 调用来拉权限，与登录解耦导致竞态和权限查找问题。
- **修复（一箭三雕）**：
  - **后端**：`LoginResponse` 增加 `List<String> permissions` 字段；`AuthService.login/register` 注入 `RoleService` 查询当前角色的权限码并随登录响应一并返回。
  - **前端**：`Login.vue` 从 `res.data` 解构 `permissions`；`authStore.setLogin()` 改为 **同步**接收 `userPermissions` 并立即写入 Pinia + localStorage，登录后权限立即可用。
  - 零竞态：权限与 token 同步到达，路由守卫读到的是已填充的 Set。
  - **数据库**：给 `EDU_ADMIN` 和 `FINANCE` 角色补回 `menu:dashboard` 权限（历史 `is_deleted=1` 行改回 `is_deleted=0`）。
- **验证**：
  - admin 登录 → 22 权限（内含 dashboard）✅
  - edu 登录 → 11 权限（教务 + dashboard）✅
  - finance 登录 → 6 权限（财务 5 + dashboard）✅
- **涉及文件**：
  - `LoginResponse.java`（加 permissions 字段）
  - `AuthService.java`（注入 RoleService，login/register 加载权限）
  - `auth.ts`（setLogin 同步接收 permissions，移除 fetchPermissions 竞态）
  - `Login.vue`（解构 permissions 传参）

## 19:41 修复课时流水中已删学员姓名消失
- **现象**：课时流水中部分记录"学员"列空白（包括 ID 53 刘小小、ID 38/37 刘子轩、ID 12-15 等）。
- **根因（用户猜测正确）**：学员被退课/退费触发后，`student.is_deleted=1`。`FinanceServiceImpl.populateFlowNames` 用 `studentMapper.selectBatchIds(...)` 取名，因 Student 实体带 `@TableLogic`，MP 拦截器自动加 `is_deleted=0`，已软删学员被过滤 → 名字查不到 → 显示空。
- **修复**：
  - `StudentMapper` 新增 `@Select("SELECT id, name FROM student WHERE id IN (${ids})")` 方法 `selectNamesByIdsIncludeDeleted`，返回 `List<Map<String,Object>>`。Map 返回类型让 LogicDeleteInnerInterceptor 解析不到 TableInfo，不会追加 `is_deleted=0`。
  - `FinanceServiceImpl.populateFlowNames` 改用新方法取名。
- **验证**：
  - 修复前：student_id=1,12,13,14 全部显示空
  - 修复后：id=53/42/41/17/16/1 student_id=1 → "刘小小" ✅；id=38/37 student_id=12 → "刘子轩" ✅
- **同类隐患**（未修）：`AttendanceServiceImpl`/`LeaveRequestServiceImpl`/`EnrollmentServiceImpl` 同样用 `studentMapper.selectBatchIds` 给历史记录加姓名，**理论上**也会丢学员。需逐一改造为 `selectNamesByIdsIncludeDeleted`。
- **重要规范**（MyBatis-Plus）：实体有 `@TableLogic` 时，对"需要历史/已删记录"的关联查询（`populateXxxNames` 等），不能用 `selectBatchIds`，必须用 `@Select` 注解 + 非实体返回类型（Map / 标量 / 非实体 DTO）绕过拦截器。

# 开发指南

> **版本状态**：v0.9 规划版，基于 `03`/`04`/`05` 编制，聚焦工程实施方式。

## 1. 开发流程

### 1.1 分支与提交

建议采用简化 Git 流程：

- `main`：保持可运行；
- `dev`：日常开发主线；
- `feature/mobile-parent-teacher`、`feature/admin-schedule`、`feature/finance` 等：按终端或模块开发；
- 提交信息建议使用 `feat: 实现教师端移动考勤`、`feat: 实现管理后台排课冲突检测`、`docs: 更新接口规范` 等格式。

### 1.2 模块开发顺序

| 顺序 | 模块 | 说明 |
|---|---|---|
| 0 | 基础设施 | 后端统一响应、异常处理、JWT、角色权限；移动端和后台请求封装 |
| 1 | 用户与权限 | 登录、用户、角色、菜单、操作日志、机构配置；移动端和后台共用登录接口 |
| 2 | 学员与课程 | 学员档案、家长绑定、课程类型、班级、班级学员 |
| 3 | 报名与收费 | 家长移动端报名、后台报名审核（留位时限）、缴费、续费、课时账户初始化 |
| 4 | 排课与教室 | 管理后台批量排课、冲突检测（教师/教室/班级/学员/容量）、调课审批、教室预约；移动端展示课表、提交/查看调课申请 |
| 5 | 考勤与学情 | 教师移动端考勤、作业、评语；家长移动端查看学情与课时 |
| 6 | 财务与薪资 | 管理后台收费台账、退费审核、课时消耗、教师薪资结算 |
| 7 | 考级与通知 | 管理后台维护考级和公告，移动端接收考级通知与上课提醒 |
| 8 | 统计与报表 | 管理后台招生、到课率、营收、课时趋势、工作量、报表导出 |
| 9 | 联调与测试 | uni-app 端、Vue3 后台、Spring Boot 后端全流程联调 |

## 2. 后端开发指南

### 2.1 工程结构

```
backend/
├── src/main/java/com/pzhu/eduadmin/
│   ├── common/            # Result、异常、分页、枚举、工具类
│   ├── config/            # Web、CORS、Redis、MyBatis、Swagger配置
│   ├── security/          # JWT、拦截器、权限注解
│   ├── modules/
│   │   ├── auth/          # 登录认证
│   │   ├── user/          # 用户、角色、权限
│   │   ├── student/       # 学员、家长关系
│   │   ├── course/        # 课程、班级
│   │   ├── enrollment/    # 报名审核
│   │   ├── schedule/      # 排课、教室、调课
│   │   ├── attendance/    # 考勤、课时扣减
│   │   ├── learning/      # 作业、学情记录
│   │   ├── finance/       # 收费、退费、课时账户
│   │   ├── salary/        # 薪资规则、薪资结算
│   │   ├── exam/          # 考级管理
│   │   ├── notice/        # 公告通知
│   │   └── statistics/    # 统计看板、报表导出
│   └── EduAdminApplication.java
└── src/main/resources/
    ├── application.yml
    ├── mapper/
    └── sql/
```

### 2.2 分层约定

| 层 | 职责 |
|---|---|
| Controller | 参数接收、校验、调用 Service、返回统一响应 |
| Service | 业务规则、事务控制、跨模块编排 |
| Mapper | 数据访问，复杂统计 SQL 写 XML |
| Entity | 数据库表映射，不直接返回移动端或管理后台 |
| DTO/VO | 请求入参和响应出参，移动端和后台可按展示差异定义不同 VO |

### 2.3 关键实现提示

| 主题 | 实现提示 |
|---|---|
| 权限 | JWT 解析当前用户，接口用角色注解或拦截器校验 |
| 终端隔离 | 家长/教师接口使用 `/api/parent`、`/api/teacher`，后台接口使用 `/api/edu`、`/api/finance`、`/api/admin` |
| 排课 | 冲突检测逻辑集中在 `ScheduleConflictService`，覆盖教师/教室/教室预约/班级/学员五个时间交叉维度及教室容量校验，避免多个接口重复判断 |
| 调课 | 教师提交 `schedule_adjust_request`，教务审批通过后才落地新课次并关联 `source_lesson_id`；教务直接手动调课可跳过申请表 |
| 课时 | 扣减课时必须同时更新账户余额和写入流水，放在同一事务，且需使用 `lesson_account.version` 乐观锁防止并发扣减超扣 |
| 财务 | 收费、退费、薪资确认均记录操作日志；退费金额不得超过该报名累计已缴费金额，退费申请人与审核人不可为同一人 |
| 统计 | 高频看板可预计算到 `statistics_snapshot`，普通统计可实时聚合 |
| 报表 | Excel 导出建议封装统一 `ExportService` |

## 3. 移动端开发指南（uni-app）

```
├── store/
├── utils/request.js
├── pages.json

```

### 3.2 移动端开发重点

- 家长端以“看”为主：课表、学情、课时、通知、报名记录；
- 教师端以“课堂即时操作”为主：查看课表、提交考勤、发布作业、填写评语；
- 页面布局优先适配手机屏幕，表单字段短、操作按钮明确；
- 调试阶段优先跑 H5，演示小程序时使用微信开发者工具。

## 4. 管理后台开发指南（Vue3）

### 4.1 工程结构

```
admin-web/
├── src/
│   ├── api/               # auth、student、course、schedule、finance等接口封装
│   ├── views/
│   │   ├── edu/
│   │   ├── finance/
│   │   └── admin/
│   ├── components/        # 通用表格、表单、上传、图表、课表组件
│   ├── router/            # 路由与权限守卫
│   ├── store/             # Pinia 状态
│   └── api/request.ts     # Axios封装 (TypeScript)
```

### 4.2 后台开发重点

公共登录与布局 → 管理端用户权限 → 教务课程班级 → 排课课表 → 财务收费薪资 → 统计看板 → 报表导出。

后台页面优先复用 `DataTable`、`FormDialog`、`ChartPanel`、`ScheduleCalendar`，降低重复开发量。

## 5. 联调约定

- JSON 字段统一驼峰命名；
- 分页请求统一 `pageNum`、`pageSize`；
- 响应统一 `{ code, message, data }`；
- 时间格式统一 `yyyy-MM-dd HH:mm:ss`；
- Token 统一放在 `Authorization: Bearer {token}`；
- 移动端和管理后台均以 `09-接口规范.md` 为接口字段来源。

## 6. Mock 与测试数据

uni-app 和 Vue3 后台均可先按 `09-接口规范.md` 使用 Mock 数据开发页面；后端准备初始化 SQL，包括五类角色账号、课程、教师、教室、学员、班级、课次、收费和考勤记录，保证移动端和后台都有可演示数据。

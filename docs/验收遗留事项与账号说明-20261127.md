## 一、四项决策结论

### 1. 财务看板范围 =「分层可见」设计，维持现状（终态）

| 内容 | 财务可见性 | 证据 |
|---|---|---|
| 营收 / 课程盈利 / 收费率 Tab | ✅ 可见 | 决策保留（答辩信息量） |
| 流失预警**汇总数字**（总数/高/中/低 4 个 chips） | ✅ 可见 | summary 接口实测 200 |
| 流失预警**学员级名单** | ❌ 不可见 | `RiskWarningController:34 @RequireRole({SUPER_ADMIN, EDU_ADMIN})`，finance 实测 **403** |
| 名单勾选 / 跟进下拉 / **导出名单按钮** | ❌ 不可见 | 前端 `v-if="canOperate"`（RiskWarningPanel:132） |

**分层口径**：汇总数字可给财务（管理层视角），学员级名单与导出严格收敛到超管/教务。
连续多轮复测报「名单全在」实为把汇总 chips 误读为名单——代码侧实测 403 为铁证。

### 2. `edu_admin` 账号 = 复测方基线文档笔误，不补账号

全仓库不存在把账号写成 `edu_admin` 的任何文案：

- 登录页演示提示 `Login.vue:41-49`：`admin / 123456`、`edu / 123456`、`finance / 123456`
- `README.md:88-98` 与论文附录 `docs/thesis/09-附录A:83-91`：教务管理员为 **`edu`**
- `edu_admin` 仅为**数据库名**（application.yml / compose 环境变量）

**请复测方修正其基线文档中的账号名**：教务账号为 `edu`。

### 3. 内置弱口令 = 已知事项，验收披露

- **新设密码已强制强度**（`common/PasswordPolicy`：≥6 位且必须含字母+数字），
  实测 `123456`、`abcdefgh` 提交改密均被 400 拦截——**增量侧已闭环**
- 内置三账号（admin / edu / finance）密码 `123456` **保留**，为答辩演示便利；
  属已知事项，如后续上线真实机构，验收后执行一轮强制改密即可（机制已具备：
  重置密码自动置 `must_change_password=1` 强制首登改密）

### 4. 导出 = **直链已上线**，第五轮复测的导出结论过时

第五轮复测（21:45–22:10）测到的仍是 blob 版本；`0374898` 已将 GET 导出改为
**一次性票据直链下载**（`…26o` 镜像同批上线）：

- 前端点导出 → Bearer 换 60s 一次性票据（绑定端点、取出即删）→ `<a href>` 浏览器原生下载
- 冒烟实测：直链 200 xlsx 8015B、重放 401、跨端点挪用 401、非法端点 400、
  FINANCE 200 / EDU 403（票据路径下 @RequireRole 生效）
- **请重测一次导出**：这次应直接进入浏览器下载条，不再出现 `.crdownload` 卡住；
  若 60 秒内重复点击同一导出会提示票据过期，重新点击即可（防重放设计）

# 项目开发计划

> **版本状态**：v0.9 规划版，基于 `项目.md` 和 `00-文档说明.md` 编制。

## 1. 项目信息

- **项目名称**：艺术培训机构全流程教务管理平台的设计与实现
- **技术路线**：Spring Boot + uni-app 移动端 + Vue3 管理后台前后端分离，MySQL + Redis，ECharts 图表展示
- **项目目标**：完成一个包含学员家长、授课教师、教务管理员、财务管理员、超级管理员五类角色的教务管理系统，实现报名缴费、排课考勤、课时扣减、学情管理、薪资结算和运营统计等核心功能，并交付源代码、数据库脚本、系统文档、测试报告、毕业论文和答辩材料。

## 2. 开发模式

本项目按单人毕业设计项目组织，采用“文档先行、核心链路优先、逐模块联调”的方式推进。

- 先完成需求、概要、详细、数据库和接口设计；
- 再搭建前后端工程骨架；
- 优先打通登录、角色权限、报名缴费、排课、考勤扣课时、薪资核算和统计看板；
- 最后补充报表导出、用户手册、测试报告、论文和答辩材料。

## 3. 16 周开发进度

| 阶段 | 周次 | 主要任务 | 输出成果 |
|---|---|---|---|
| 选题与调研 | 第1周 | 分析艺术培训机构教务管理现状，明确系统边界和五类角色 | 题目说明、问题定义 |
| 可行性与需求分析 | 第2周 | 编写可行性研究、需求规格说明书，细化功能需求和非功能需求 | `01`、`03` |
| 概要设计 | 第3周 | 确定系统架构、模块划分、技术选型和部署方案 | `04` |
| 详细设计 | 第4周 | 设计数据库、接口、核心业务流程和算法规则 | `05`、`09`、`10`、`12` |
| 环境与脚手架 | 第5周 | 搭建 Spring Boot 后端、uni-app 移动端与 Vue3 管理后台、MySQL/Redis 环境 | 工程骨架、初始化配置 |
| 基础模块 | 第6周 | 实现登录认证、角色权限、用户管理、机构配置 | 可登录系统、权限菜单 |
| 学员与课程模块 | 第7周 | 实现学员档案、课程类型、班级、报名审核、收费与课时账户初始化（对齐 `08`/`15` 顺序：课时账户须先于排课与考勤存在） | 学员/课程/班级管理、可缴费开通课时账户 |
| 排课模块 | 第8周 | 实现批量排课、冲突检测（教师/教室/班级/学员/容量）、调课审批、教室预约 | 排课与课表功能 |
| 考勤与学情模块 | 第9周 | 实现课堂考勤、课时扣减（基于第7周已创建的课时账户）、作业、教师评语 | 考勤扣课时闭环 |
| 财务模块 | 第10周 | 实现续费、退费审核（含上限校验）、课时流水查询 | 退费流程、课时流水报表 |
| 薪资与考级模块 | 第11周 | 实现教师课时统计、薪资结算、考级报名和成绩归档 | 薪资单、考级记录 |
| 统计与报表 | 第12周 | 实现招生、到课率、营收、课时趋势、教师工作量看板 | ECharts 看板、报表导出 |
| 系统联调 | 第13周 | 前后端全流程联调，补齐异常处理和通知消息 | 可演示系统 |
| 测试与修复 | 第14周 | 按测试计划执行功能、接口、安全和性能测试 | 测试记录、缺陷修复 |
| 论文与手册 | 第15周 | 编写毕业论文、用户操作手册、测试报告 | 论文初稿、手册、报告 |
| 答辩准备 | 第16周 | 准备 PPT、演示数据、演示账号，完成最终回检 | 答辩材料、最终系统 |

## 4. 里程碑

| 里程碑 | 完成标准 |
|---|---|
| M1 文档规划完成 | `00-16` 文档主题一致，覆盖任务书要求 |
| M2 工程骨架完成 | 前后端可启动，数据库可连接，登录接口可用 |
| M3 核心教务链路完成 | 报名、排课、考勤、课时扣减可完整演示 |
| M4 财务薪资链路完成 | 收费、退费、薪资结算可完整演示 |
| M5 统计看板完成 | 多维度统计图表与报表导出可用 |
| M6 毕设交付完成 | 系统、脚本、文档、论文、答辩材料齐全 |

## 5. 质量保障措施

- 文档与代码同步：接口、数据库字段和核心业务规则变更时同步更新对应文档；
- 核心规则测试：排课冲突、课时扣减、退费、薪资核算必须有明确测试用例；
- 数据一致性：涉及课时、收费、退费、薪资的操作使用事务控制；
- 安全控制：登录鉴权、角色权限和敏感操作日志作为基础能力优先实现；
- 演示数据：准备覆盖五类角色的初始化账号和业务数据。

## 6. 风险与应对

| 风险 | 可能影响 | 应对措施 |
|---|---|---|
| 功能过多 | 无法全部高质量完成 | 优先核心链路，扩展功能标注为可选 |
| 排课算法复杂 | 排课功能延期 | 采用规则检测 + 手动调整，保证可运行 |
| 多角色页面多 | 移动端与管理后台开发量大 | 复用布局、表格、表单、图表组件 |
| 测试数据不足 | 看板无展示效果 | 提前准备模拟学员、课程、课次、收费和考勤数据 |
| 论文与系统不一致 | 答辩风险 | 第15-16周进行文档、代码、截图统一回检 |

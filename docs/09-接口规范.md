# 接口规范

> **版本状态**：v1.0 正式版，已与实际代码和测试结果核对，验收日期 2026-07-19。

## 1. 通用规范

### 1.1 基础路径

所有接口以 `/api` 为统一前缀。

### 1.2 统一响应

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

### 1.3 分页响应

```json
{
  "total": 100,
  "pageNum": 1,
  "pageSize": 10,
  "records": []
}
```

### 1.4 鉴权

请求头：`Authorization: Bearer {token}`。

### 1.5 通用错误码

| code | 含义 |
|---|---|
| 0 | 成功 |
| 400 | 参数错误 |
| 401 | 未登录或登录过期 |
| 403 | 无权限 |
| 404 | 数据不存在 |
| 409 | 业务状态冲突 |
| 500 | 系统异常 |

### 1.6 权限标注约定

除第 2 节鉴权模块外，各角色端接口默认要求对应角色登录（如家长端接口默认要求 `PARENT` 角色，教务端接口默认要求 `EDU_ADMIN` 角色），仅在有额外限制或跨角色场景时单独在"权限"列标注。

### 1.7 数据行级归属校验

家长端所有携带 `studentId`/`{id}` 的接口，后端 Service 层必须校验该学员是否在当前登录家长（从 JWT 中解析的 `parent_user_id`）的 `parent_student` 绑定列表中，未绑定按 403 处理；教师端携带 `lessonId` 的接口同理校验该课次是否属于当前教师或其代课范围。角色注解只做粗粒度的"能否访问该类接口"校验，不能替代该行级归属校验（详见 `05` §8 安全设计）。

## 8. 关键请求字段示例

### 8.1 批量排课

```json
{
  "classId": 1,
  "teacherId": 2,
  "classroomId": 3,
  "startDate": "2026-09-01",
  "endDate": "2026-12-31",
  "weekdays": [2, 4],
  "startTime": "18:00",
  "endTime": "19:30"
}
```

### 8.2 提交考勤

```json
{
  "records": [
    { "studentId": 1, "status": 1, "remark": "正常到课" },
    { "studentId": 2, "status": 2, "remark": "请假" }
  ]
}
```

### 8.3 生成薪资

```json
{
  "teacherId": 2,
  "salaryMonth": "2026-07"
}
```

# 接口规范

> **版本状态**：v1.3.0 正式版，已与实际代码和测试结果核对，同步日期 2026-10-04。

## 1. 通用规范

### 1.1 基础路径

所有接口以 `/api` 为统一前缀。

### 1.2 统一响应

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

### 1.3 分页响应

```json
{
  "total": 100,
  "pageNum": 1,
  "pageSize": 10,
  "records": []
}
```

### 1.4 鉴权

请求头：`Authorization: Bearer {token}`。

**登录失败锁定**（Redis 双维度，`LoginAttemptService`）：

- 账号维度：连续失败 **5 次** 锁定 15 分钟
- IP 维度：同一 IP 失败 **30 次** 锁定（防撞库）
- 解锁：管理端「用户管理 → 解锁」入口，或锁定到期自动恢复

**防探测设计**：登录失败的三种情形（用户不存在 / 账号已停用 / 密码错误）**返回完全一致的文案**，不区分原因，避免攻击者借此确认用户名是否存在；停用账号的登录尝试**不记入失败计数**（非凭据错误）。因此账号被停用后登录提示仍为"用户名或密码错误"，属预期行为而非缺陷。

### 1.5 通用错误码

| code | 含义 |
|---|---|
| 0 | 成功 |
| 400 | 参数错误 |
| 401 | 未登录或登录过期 |
| 403 | 无权限 / 需强制修改密码（见下） |
| 404 | 数据不存在 |
| 409 | 业务状态冲突 |
| 429 | 请求过于频繁（限流） |
| 500 | 系统异常 |

**403 有两种语义，以 `message` 区分，不新增业务码：**

- `message = "无权访问该接口"` —— 角色不足，按通用无权限处理。
- `message = "NEED_CHANGE_PASSWORD"` —— 账号密码非本人设置（管理员代设或重置过），须先改密。此时除下列 4 条白名单外，所有接口均返回该值：

  `/api/auth/password`、`/api/auth/logout`、`/api/auth/profile`、`/api/auth/menus`

  前端必须**先于通用 403 分支**匹配 `code === 403 && message === 'NEED_CHANGE_PASSWORD'` 并跳转改密页，否则用户会被误导成"权限不足"，无法自救。

**429 目前仅 `GET /api/teacher/students/{studentId}/parent-contact` 使用**：60 次/分钟，Redis 计数，Redis 不可用时降级为进程内计数（限流是压力保护，不是权限边界；真正的边界是任教关系判定）。

### 1.6 权限标注约定

除第 2 节鉴权模块外，各角色端接口默认要求对应角色登录（如家长端接口默认要求 `PARENT` 角色，教务端接口默认要求 `EDU_ADMIN` 角色），仅在有额外限制或跨角色场景时单独在"权限"列标注。

### 1.7 数据行级归属校验

家长端所有携带 `studentId`/`{id}` 的接口，后端 Service 层必须校验该学员是否在当前登录家长（从 JWT 中解析的 `parent_user_id`）的 `parent_student` 绑定列表中，未绑定按 403 处理；教师端携带 `lessonId` 的接口同理校验该课次是否属于当前教师或其代课范围。角色注解只做粗粒度的"能否访问该类接口"校验，不能替代该行级归属校验（详见 `05` §8 安全设计）。

**教师端按 `studentId` 判权（新增）**：`GET /api/teacher/students/{studentId}/parent-contact` 不走 `lessonId`，判权取**并集**且刻意排除历史：

```
(A) class_group.teacher_id = 当前教师 且 班级 status = 1 且 学员在班
(B) 存在 status = 1 且 lesson_date >= 今天 的课次 且 学员在班
```

不得复用既有的 `verifyTeacherStudentAccess`（它只判"曾经有过任意课次"，未过滤状态与日期），否则离职教师凭历史课次可永久查看家长电话。命中后写审计日志（`target_type=STUDENT`、`target_id=studentId`）。

## 8. 关键请求字段示例

### 8.1 批量排课

```json
{
  "classId": 1,
  "teacherId": 2,
  "classroomId": 3,
  "startDate": "2026-09-01",
  "endDate": "2026-12-31",
  "weekdays": [2, 4],
  "startTime": "18:00",
  "endTime": "19:30"
}
```

### 8.2 提交考勤

> **审计设计**：考勤不提供 DELETE 或修改接口（删除/改判返回 405）——考勤直接联动课时扣减流水，事后更正一律走「人工调整课时」入口（source_type=5 流水留痕），保证账目链完整可追溯。

```json
{
  "records": [
    { "studentId": 1, "status": 1, "remark": "正常到课" },
    { "studentId": 2, "status": 2, "remark": "请假" }
  ]
}
```

### 8.3 生成薪资

```json
{
  "teacherId": 2,
  "salaryMonth": "2026-07"
}
```

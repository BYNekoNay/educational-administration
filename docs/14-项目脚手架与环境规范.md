## 5. mobile-uniapp 配置建议

- 使用 HBuilderX 或 CLI 模式创建项目；
- `manifest.json` 配置应用名称、AppID 和平台能力；
- `pages.json` 维护家长端、教师端页面路由；

```js

```

- 4 类课程：美术、钢琴、舞蹈、书法；
- 3-5 名教师；
- 3 个教室；
- 10 名学员和对应家长；
- 若干班级、课次、考勤、收费和薪资规则；
- 至少一组排课冲突演示数据。

## 8.5 数据库迁移规范

存量/生产库的结构变更一律走 Flyway（`backend/src/main/resources/db/migration/`，仅 prod profile 启用），全新建库用 `sql/schema.sql` + `sql/data.sql`。当前最新迁移 **V11**。

**三条硬性要求**（完整说明见 `10-数据库规范.md` §1.1）：

1. **迁移必须幂等**：`ADD COLUMN` 前查 `information_schema.COLUMNS`、`CREATE INDEX` 前查 `information_schema.STATISTICS`，用 `PREPARE / EXECUTE / DEALLOCATE` 条件执行。原因不是洁癖——MySQL 的 `ALTER TABLE` 隐式提交且不可回滚，中途失败会留下已执行的 DDL 而版本号没推进，下次启动因 `Duplicate column name` **永久卡住**，只能人工进库处理。
2. **种子数据必须两份**：迁移脚本用 `INSERT IGNORE`（供存量库），同时同步 `sql/data.sql`（供全新建库）；`sys_menu` 因 `permission_code` 无唯一键，需先取计数到变量再 `PREPARE`（直接写 `INSERT ... WHERE NOT EXISTS` 会触发 ERROR 1093）；三表顺序固定 `permission → sys_menu → role_permission`。
3. **发布前同步版本号**：`deploy/scripts/release-production.sh:12` 的 `EXPECTED_SCHEMA_VERSION` 必须等于最新迁移号（当前 **11**），否则发布门禁直接失败。

## 9. 开发命令建议

后端：

```bash
mvn spring-boot:run
```

管理后台：

```bash
cd admin-web
npm install
npm run dev
```

uni-app：

- 使用 HBuilderX 运行到浏览器，或使用 CLI 运行 H5（npm run dev:h5）；
- 小程序构建命令（build:mp-weixin）已保留，未纳入本次交付验证。

打包：

```bash
cd admin-web
npm run build
cd ..
mvn clean package
```

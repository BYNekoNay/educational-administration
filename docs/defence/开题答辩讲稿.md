## 1. 开场（约 0.5 分钟 · 第 1 页）

各位老师好。我是软件工程专业的学生＿＿＿，我的毕业设计题目是《艺术培训机构全流程教务管理平台的设计与实现》。下面我从选题背景、研究现状、研究内容、技术方案、进度安排与预期成果六个方面，向各位老师做开题汇报。

## 2. 选题背景与意义（约 2 分钟 · 第 2~5 页）

先讲为什么要做这个课题。

艺术培训是素质教育的重要组成部分，涵盖音乐、舞蹈、美术等多种课程形态。与学科类培训相比，它的运营特征非常鲜明：课程类型多、上课频次高、授课教师多为兼职、学员以未成年人为主、请假调课频繁；更关键的是机构收入依赖课时包销售，课时扣减与教师薪资又长期靠人工核算。这些特征叠加在一起，让教务管理成为机构日常运营中信息密度最高、最容易出错的环节。

而大量中小型机构至今还在用电子表格和纸质登记本管理学员、课表、考勤与收费，由此产生五类痛点：一是数据分散、统计滞后，管理者难以及时掌握招生、到课、营收和流失状况；二是课时手工扣减，多学员多课程组合下极易误扣漏扣；三是排课靠经验试错，教师、教室、班级的时间冲突要等使用中才发现；四是教师薪资人工汇总，慢、易错、缺明细；五是学员流失隐蔽，等续费明显下滑才被察觉，往往已错过干预窗口。随着规模扩大，人力与差错成本呈非线性上升，成为制约机构规模化、规范化运营的瓶颈。

因此本课题具有明确的工程价值：把招生、排课、考勤、课时、财务、学情统一到同一系统与同一数据模型，流程标准化、口径一致化，消除信息孤岛；用自动化的课时扣减、冲突检测与薪资核算降低人工差错；把沉淀的数据变成运营看板与流失预警，让机构由事后统计转向事前干预。

## 3. 国内外研究现状（约 1.5 分钟 · 第 6~7 页）

再看研究现状。国外起步较早，与本课题最相关的两个方向是智能排课与学员流失预测：排课本质上是受多重约束的组合优化问题，国外研究用遗传算法结合动态规划求解、并引入贪心完成教室分配，也有以图着色聚类课程、以禁忌搜索分配时段的两阶段启发式方法；流失预测方面，研究普遍把它当作数据挖掘或机器学习问题，既利用入学前可获得的多源信息构建早期预测并提取关键因子，也综合学术、社会经济与公平三类因素、结合机器学习与生存分析。这些研究说明到课行为、参与程度与流失风险存在稳定关联，为我们用因子刻画流失风险提供了依据。

国内面向教培机构与教务管理的研究近年增长很快，覆盖排课系统与数据库设计、日程冲突检测、数据可视化、学情预警、薪资核算、移动端小程序、教务系统与档案管理等多个环节，但大多聚焦单一算法点或单一业务环节。这种点状成果难以拼装成可用、可靠、可维护的整体系统——这正是我们要补的缺口。总体趋势是：全流程一体化、事前预警干预、移动优先多端协同、工程质量成为底线、容器化持续交付。

## 4. 研究内容与目标（约 1.5 分钟 · 第 8~10 页）

本课题的研究对象是中小型艺术培训机构的教务管理，范围是构建覆盖招生、排课、考勤、课时、财务、学情全流程的教务管理平台。

系统面向五类角色：家长端做在线报名缴费、课表学情查看、课时查询与消息通知；教师端做授课课表、四态课堂考勤、作业点评与课时统计；教务端做课程班级管理、智能排课调课、报名审核分班与考级管理；财务端做收费退费、薪资结算与营收统计；超管端做人员权限、机构配置与全局运营看板。五类角色通过统一数据模型衔接，构成业务闭环。

第 9 页的系统功能结构图把这套功能自顶向下铺开：根节点是平台本身，第二层是五类角色，第三层是二十一项功能，与开题报告口径一致，一张图即可看清平台全貌。

在基础功能之上，我们重点攻克四类关键技术问题：一是报名决策的一致性，用报名快照配合版本校验，防止并发报名时决策依据被重复读取；二是排课易用性与并发冲突，用教师、教室、教室预约、班级、跨班学员五个时间交叉维度的冲突检测和拖拽快速调课，并以复合乐观条件防止并发编辑相互覆盖；三是薪资核算的正确性与不可篡改性，用状态机与并发控制保证已确认薪资不被覆盖、变更以调整记录留痕；四是运营决策能力，用可解释的多因子规则做学员流失预警，把统计从展示升级为干预。

研究目标是：完成开发与分层测试后，以容器化方式部署上线并稳定运行，实现从需求分析、设计实现、测试验收到生产上线的完整交付。

## 5. 技术方案与可行性（约 1.5 分钟 · 第 11~16 页）

技术路线上，本课题采用前后端分离的 B/S 架构，选型依据是团队熟悉度、生态成熟度与部署成本。管理后台用 Vue 3 与 Element Plus，配合 ECharts 承载大课表、薪资核算、运营看板等数据密集页面；移动端用 uni-app，以 H5 形态交付，契合家长和教师的高频轻量场景（并保留后续编译到微信小程序与 App 的能力）；后端用 Spring Boot 3.2.5 与 MyBatis-Plus 提供统一接口，两类终端共用同一套业务规则；数据库用 MySQL 8.0，结构变更由 Flyway 版本化迁移；认证用 JWT 配合基于角色的鉴权实现五类角色权限隔离。系统按客户端、接口鉴权、业务服务、数据访问、基础设施五层组织，共设计 37 张表、八个业务域；核心算法围绕五维冲突检测、课时自动扣减、薪资自动核算与流失预警评分展开，遵循可解释、可实现、可测试的原则。

研究方法采用文档驱动与核心链路优先：先完成需求与设计文档，再按报名退费、排课调课、考勤课时、薪资核算、运营预警的顺序逐步实现并逐模块联调；验证采用分层测试，从单元测试、组件测试到接口验收、浏览器 UI 验收和五角色权限验收，最后容器化部署上线验证。

可行性方面：技术可行，所选框架均为成熟开源方案，四类关键技术都有工程验证过的实现机制；经济可行，开源技术栈加容器化部署，不依赖商业授权；操作可行，管理后台面向复杂管理场景、移动端面向高频轻量场景，与岗位习惯匹配。

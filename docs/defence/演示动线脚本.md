# 现场演示动线脚本

> 用途：答辩现场按五类角色顺序走通系统。本文件只做内容层（步骤、解说、截图对应），不含版式设计。
> 演示账号只写用户名，密码见论文附录 A 演示账号表；现场不对镜头或投屏暴露任何凭据。
> 「对应截图」一列只填写仓库中真实存在的文件。截图根目录：`docs/screenshots/`、`docs/evidence/2026-07-20/`、`docs/screenshots/interactive/`。若某步没有专用截图，如实标注「无专用截图」，并给出可直接复用的真实文件作为备用。

## 一、演示前准备（务必在答辩前完成）

| 序号 | 事项 | 说明 |
|------|------|------|
| P1 | 演示数据相对日期化 | 演示库为固定日期种子数据。答辩前应重置数据或让「当月」存在缴费记录，避免运营看板出现负营收被误认为缺陷（`docs/deployment-2026-09-10.md` §7 已记录该口径） |
| P2 | 确认在线环境可用 | 提前打开管理后台与移动端两个入口各走一遍，确认可登录、列表有数据、看板图表正常渲染 |
| P3 | 预置备用截图目录 | 把本文件「六、截图核对清单」中全部截图单独放一个文件夹，断网或页面异常时可整屏切换 |
| P4 | 关闭无关窗口 | 只保留演示标签页与备用截图窗口，避免误点到其它站点或暴露书签栏中的地址 |
| P5 | 数据口径备忘 | 若被问「在册学员」与「学员列表」数量不一致：看板统计的是在班人次去重后的在册学员数，两者口径统一后应一致（`docs/ui-test-report-final-2026-09-10.md` 第五节 ISSUE-001） |

## 七、出错预案

> 原则：先稳住节奏，再用备用截图圆场，绝不在现场反复点同一个坏掉的步骤。所有备用截图必须提前打开放在独立窗口。

| 编号 | 可能出现的情况 | 现场处置动作 | 圆场话术 |
|------|---------------|-------------|---------|
| E1 | 某步点错、进错页面 | 直接点「返回」或左侧菜单回到正确页面继续，不解释、不道歉，保持节奏 | 若被察觉，一句带过：「我们回到刚才那条主线。」 |
| E2 | 页面加载慢或数据未返回 | 停留不要超过 2 秒，立即切到该步的备用截图继续讲 | 「演示环境网络有波动，我调出刚才同一页面的截图，数据是一致的。」 |
| E3 | 列表数据为空或统计为 0 | 不纠缠，切备用截图 | 「演示库是固定日期数据，当前时段没有新增，看一下有数据的这张截图。」 |
| E4 | 运营看板出现负营收 | 主动说明口径，不要慌 | 「当月缴费为 0、有退费留存时，营收口径就会是负的，这是口径正常，不是缺陷。」（依据 `docs/deployment-2026-09-10.md` §7） |
| E5 | 拖拽调课拖不动或冲突提示异常 | 放弃现场拖拽，改用备用截图讲「状态加旧时间」的并发保护 | 「现场拖拽依赖浏览器事件，我直接用截图说明这次改动的并发保护设计。」 |
| E6 | 移动端图标或页面显示异常 | 大概率是缓存，先按刷新；仍异常则切备用截图，并说明构建产物修复过 | 「移动端历史上出过一次构建产物缺静态资源导致图标 404，已经修复并复验过；这里用修复后的截图。」 |

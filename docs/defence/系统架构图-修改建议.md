# 系统架构图（P14）· 修改建议

|---|---|---|
| 客户端层 | `Web 管理后台 \| Vue3 · Vite · Pinia · Element Plus · ECharts`　`移动端 H5 \| uni-app · uView Plus（家长 / 教师）` | 不变 |

## 先说好的

- 分层正确（客户端 → 接口鉴权 → 业务服务 → 数据访问 → 基础设施），自上而下依赖方向合理
- 每层左侧色带 + 同层内元素同色，视觉区分度高
- 底部"部署链路"条把 HTTPS/反向代理 → Web 容器 → 业务接口 → 数据库容器 串起来，收尾干净

---

## 🔴 一、业务服务层只有 8 块，覆盖不全（最需要改的一处）

现状 8 块：报名管理 / 排课管理 / 考勤管理 / 课时管理 / 财务管理 / 薪资管理 / 统计预警 / 通知管理

对照功能结构图（P10）的 21 项与五类角色，**超级管理员与教务管理员的核心功能在架构图里没有落点**：

| 缺失的能力 | 对应角色 | 现状 |
|---|---|---|
| 用户 / 角色 / 权限 / 菜单 | 超级管理员 | 只在接口层有"RBAC 权限校验"，**服务层无对应模块** |
| 机构配置 | 超级管理员 | 无 |
| 学员档案、转班退班 | 教务管理员 | 仅"报名管理"沾边 |
| 课程类型 / 班级管理 | 教务管理员 | 无（只有"排课管理"） |
| 考级管理 | 教务管理员 | 无 |
| 学情 / 作业点评 | 教师、家长 | 无 |
| 公告管理 | 超级管理员 | 仅"通知管理"沾边 |

**建议**：业务服务层由 8 块补到 **10 块**，排成 2 行 × 5 列：

```
报名管理 | 排课管理 | 考勤管理 | 课时管理 | 财务管理
薪资管理 | 统计预警 | 通知公告 | 学员课程 | 用户权限
```

> 备选（改动更小）：保持 8 块，在"业务服务层"标题右侧加一行小字说明
> "另有用户权限、学员课程、考级与文件服务等支撑模块"。

---

## 🟠 二、数据访问层三块语义重复

现状：`MyBatis-Plus` / `数据读写封装` / `聚合查询`

"MyBatis-Plus" 本身就是做数据读写封装的，两块重了。

**建议改为**：`MyBatis-Plus（ORM 映射）` / `分页与乐观锁插件` / `多表聚合查询`

> 依据：系统实际装了 MyBatis-Plus 的分页插件、乐观锁插件与 BlockAttack 防全表操作拦截器，"插件"是真实存在的组件，比"数据读写封装"这个空泛说法更有信息量。

---

## 🟠 三、层间依赖箭头太弱

现状：层与层之间只有一个很小的橙色三角，位于中部偏右，看起来更像"分隔装饰"而不是"依赖方向"。

**建议**（二选一）：
- (a) 在图的**最左侧**加一条贯穿全图的纵向箭头，标注"依赖方向"，五个层间不再放小三角；
- (b) 保留层间箭头，但**放大并置于每层水平居中**，避免被"薪资管理/统计预警"这类文字压住。

---

## 🟡 四、可选加分项

1. **加"横切关注点"竖带**：在最右侧加一条窄竖带，涵盖 安全（JWT/RBAC/数据行级隔离）、事务与并发（乐观锁 CAS）、日志与审计、监控（Actuator 健康探针）。架构图有横切带会显得更完整。
2. **基础设施层补"反向代理"**：现在反向代理只出现在底部"部署链路"条里。可把该条并入基础设施层，或基础设施层补一块——避免同一信息两处出现。
3. **客户端层文字风格统一**：客户端层两块是"粗体标题 + 小字技术栈、左对齐"，其余各层是"居中单行"。建议统一对齐方式。
4. **小字放大**：客户端层的 `Vue3 Vite Pinia Element Plus ECharts` 与 `uni-app uView Plus（家长 / 教师）` 在投影上偏小，建议字号 +2pt。
5. **与 P13 口径互证**：P13 写"37 张表，按八个业务域组织"，P14 业务服务层若补到 10 块，注意别让"八个业务域"与"十个服务"看起来冲突 —— 可在 P13 或 P14 其中一处加"域/服务"的对应说明。

---

## 一句话总结

P14 的**分层骨架没问题、不用重做**；只需要把**业务服务层从 8 块补到 10 块**（让超管与教务的功能有落点），顺手修掉数据访问层的语义重复与层间箭头偏弱这两处即可。

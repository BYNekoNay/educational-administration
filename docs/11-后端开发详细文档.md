# 后端开发详细文档

> **版本状态**：v0.9 规划版。本文档细化 Spring Boot 后端模块实现方案。

## 1. 公共基础模块

### 1.1 统一响应

实现 `Result<T>`：`code`、`message`、`data`。所有 Controller 返回统一结构。

### 1.2 异常处理

使用 `@RestControllerAdvice` 捕获业务异常、参数校验异常和系统异常。业务异常建议包含错误码和提示文案。

### 1.3 鉴权与权限

- 登录成功签发 JWT；
- 拦截器解析 Token 并保存当前用户上下文；
- 通过角色注解或权限表校验接口访问；
- 资源归属在 Service 层二次校验。

## 2. 用户与权限模块

| 类 | 职责 |
|---|---|
| AuthController | 登录、退出、当前用户信息 |
| UserController | 用户增删改查、启用禁用 |
| RoleController | 角色与权限配置（基于 `role_permission` 关联表） |
| OrganizationController | 机构信息配置查询/更新 |
| AuthService | 密码校验、Token 签发 |
| PermissionService | 菜单和接口权限计算 |

关键点：密码使用 BCrypt；禁用账号禁止登录；角色包括 PARENT、TEACHER、EDU_ADMIN、FINANCE、SUPER_ADMIN，`user.role_code` 须在应用层校验其值存在于 `role.role_code`。

## 3. 学员、课程与报名模块

### 3.1 学员模块

维护学员档案、家长绑定关系。家长端接口按 `studentId` 查询前，Service 层必须校验该学员是否在当前家长的 `parent_student` 绑定列表中（校验未通过返回 403），防止越权访问其他家长的学员数据。

### 3.2 课程与班级模块

课程包含课时、时长、价格等套餐信息；班级关联课程、教师和容量（`max_student_count`）。班级加人（`class_student` 写入）时需校验当前人数是否已达 `max_student_count`，报名审核通过分班时、缴费成功正式入班时均需重复校验，防止并发报名导致超员。

### 3.3 报名模块

报名申请状态：待审核（1）、待缴费（2）、已完成（3）、已拒绝（4）、已失效（5）。审核通过后仅记录意向 `class_id` 并进入"待缴费"状态，设置 `hold_expire_time` 留位时限，由定时任务扫描超时未缴费的记录并转为"已失效"释放名额；缴费成功后才正式写入 `class_student` 并将状态置为"已完成"。

## 4. 排课模块

### 4.1 ScheduleConflictService

集中处理冲突检测：

- 教师同时间冲突；
- 教室同时间冲突；
- 班级同时间冲突；
- 学员同时间冲突（同一学员通过 `class_student` 关联的不同班级课次之间）；
- 教室预约冲突（`room_booking`）。

时间交叉条件：`existing.start < new.end && existing.end > new.start`。查询范围仅限 `schedule_lesson.status IN (1,2)`（待上课、已完成），已取消（3）与已调课（4）的旧课次不参与判断。

### 4.2 批量排课

`ScheduleService.batchCreate` 根据日期范围和星期生成候选课次，逐条检测冲突，无冲突后批量插入。若部分冲突，建议整体失败并返回冲突明细，便于教务统一调整。

### 4.3 调课

教师通过 `ScheduleAdjustRequestController` 提交 `schedule_adjust_request`（状态"待审核"）。教务审批：

- 通过：调用 `ScheduleConflictService` 复核新时间/教师/教室后，将原课次状态改为"已调课"，新建目标课次并记录 `source_lesson_id`，`schedule_adjust_request.status` 置为"已通过"；
- 驳回：`schedule_adjust_request.status` 置为"已驳回"，原课次不变。

教务也可通过 `ScheduleController.adjust` 跳过申请表直接手动调课。调课成功后生成通知（对应 `NoticeService`，见 §8）。

## 5. 考勤、课时与学情模块

### 5.1 考勤提交

教师提交课次考勤时，后端校验：

- 当前课次属于该教师或教师有代课权限；
- 同一课次同一学员不能重复考勤；
- 课次状态允许考勤。

### 5.2 课时扣减

扣课时流程必须在事务内完成：校验是否已有考勤记录（有则先回冲原扣减）→ 保存/更新考勤 → 计算扣课时 → 查询课时账户（`SELECT ... FOR UPDATE` 或乐观锁）→ 校验余额 → 更新余额（`version` 乐观锁递增）→ 写课时流水。余额为 0 且考勤状态为"到课"时阻止提交，提示先续费；余额不足但大于 0 时允许扣至 0 并标记欠费，不允许扣成负数。详细伪代码见 `12-核心算法设计文档.md` §4.2。

### 5.3 学情记录

`HomeworkService` 负责课次作业，`LearningRecordService` 负责每个学员的课堂表现、教师评语和成长标签。

## 6. 财务模块

### 6.1 收费与续费

收费成功后写入 `payment_record`，并增加 `lesson_account.remaining_lessons`，同步写入 `lesson_flow`。

### 6.2 退费审核

退费申请写入 `refund_record`（关联 `payment_record_id`、`enrollment_id`），建议退费金额 = 剩余课时 × 课时单价，并强制校验不超过"该 `enrollment` 累计已缴费金额 - 累计已退费金额"，超出部分需财务人工核实（可能是降价或优惠导致）。若审核人与申请人为同一账号，系统自动转交其他财务人员复核。审核通过后减少课时账户余额（乐观锁更新）或标记课程结束，写入负向 `lesson_flow`；若该学员在未来已排课次的班级名额因退费不再需要，联动将 `class_student.status` 置为"已退出"。

## 7. 薪资模块

`SalaryService.calculate(month, teacherId)`：

1. 记录本次核算的 `calc_snapshot_time`（当前时间）；
2. 查询截至该时间点教师当月已完成课次，并校验每个课次存在有效考勤记录（无考勤登记的课次不计入薪资）；
3. 统计主讲课时和代课课时；
4. 读取薪资规则；
5. 计算基础工资、代课工资、奖金补贴和应发工资；
6. 生成 `teacher_salary`，写入 `calc_snapshot_time`。

已确认的薪资单（status=2）不可覆盖。若确认后课次/考勤发生变更，通过 `SalaryAdjustmentService` 写入 `salary_adjustment` 记录差额，教师实发金额 = `teacher_salary.total_amount` + 该单下全部调整记录之和；需要整单作废时将 `status` 置为"已撤销"（4）并重新核算生成新单。

## 8. 考级与通知模块

考级模块管理考级项目、报名学员、成绩和证书编号。通知模块用于公告、调课通知、上课提醒、课时不足提醒、报名留位到期提醒、考级通知，可先实现站内消息，短信推送作为扩展。触发规则：调课审批通过后立即通知受影响学员家长和教师；上课提醒由定时任务在课次开始前固定提前量扫描触发；课时不足提醒在考勤扣减后余额低于阈值时触发；详见 `05-详细设计说明书.md` §4.6。

## 9. 统计与报表模块

统计接口包括：招生人数、到课率、课时消耗趋势、班级活跃度、教师工作量、营收统计、课程盈利、学员流失率。报表导出统一由 `ExportService` 输出 Excel/PDF。

## 10. 日志与审计

以下操作必须记录 `operation_log`：

- 用户禁用/启用、角色权限修改；
- 报名审核、调课申请审批、删除课次；
- 收费、退费、薪资确认、薪资调整；
- 公告发布、机构配置修改。

## 11. 测试建议

优先为以下 Service 编写单元测试：

- `ScheduleConflictService`（含学员维度、状态过滤边界用例）；
- `AttendanceService.submitAttendance`（含重复提交回冲、余额为0边界用例）；
- `LessonAccountService.deduct`（含并发扣减、乐观锁重试用例）；
- `RefundService.audit`（含超上限校验、申请人审核人隔离用例）；
- `SalaryService.calculate`（含无考勤课次不计费、确认后调整记录用例）；
- `StatisticsService` 关键指标计算。

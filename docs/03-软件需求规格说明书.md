# 软件需求规格说明书（SRS）

> **版本状态**：v1.0 正式版，已与实际代码和测试结果核对，验收日期 2026-07-19。

## 1. 引言

### 1.1 编写目的

本说明书定义“艺术培训机构全流程教务管理平台”的功能性需求、非功能性需求、用户角色、数据需求和外部接口需求，作为概要设计、详细设计、开发、测试和论文撰写的依据。

### 1.2 术语定义

| 术语 | 说明 |
|---|---|
| 学员 | 在机构报名并参与课程学习的学生 |
| 家长 | 学员监护人或缴费联系人 |
| 课次 | 某班级在某一日期、时间、教室、教师下的一节具体课程 |
| 课时账户 | 记录学员某课程已购课时、剩余课时和到期时间的账户 |
| 课时流水 | 记录课时增加、消耗、退费、调整的明细 |
| 智能排课 | 根据教师、教室、班级和时间约束批量生成课次并检测冲突，检测维度含教师/教室/班级/学员/教室容量 |
| 代课 | 某课次主讲教师请假或缺席时，由另一教师临时顶替授课；该课次课时计入顶替教师的"代课课时"，按代课系数结算工资 |
| 薪资结算 | 根据教师授课课时、代课课时、课时单价和系数生成工资单 |

### 1.3 产品前景

系统面向艺术、兴趣类培训机构，服务学员家长、授课教师、教务管理员、财务管理员、超级管理员五类角色。系统通过教务、课时、学情、财务和统计一体化管理，替代传统纸质台账和分散表格，提高机构运营效率。

## 2. 总体描述

### 2.1 产品功能概述

- 学员家长：在线报名、缴费记录、课表查看、学情查看、课时余额、消息通知；
- 授课教师：个人课表、调课申请、课堂考勤、作业上传、学情点评、课时统计；
- 教务管理员：课程班级、智能排课、调课、教室预约、学员档案、报名审核、考级管理；
- 财务管理员：收费、续费、退费审核、课时消耗、教师薪资、营收统计；
- 超级管理员：人员权限、机构配置、公告管理、操作日志、全局运营看板。

### 2.2 用户特点

| 角色 | 特点 | 核心诉求 |
|---|---|---|
| 学员家长 | 使用频率中等，偏移动端查看 | 快速掌握课表、课时、学情和通知 |
| 授课教师 | 按上课节奏使用，重视操作效率 | 快速考勤、发布作业、记录课堂表现 |
| 教务管理员 | 高频使用，处理复杂排课和学员流程 | 降低排课冲突，提高教务处理效率 |
| 财务管理员 | 对数据准确性要求高 | 收费、退费、课时和薪资准确可追溯 |
| 超级管理员 | 关注全局配置和经营结果 | 权限可控、数据可视、运营可分析 |

### 2.3 假设与约束

- 支付可采用模拟支付或线下收费登记，不接入真实资金通道；
- 系统按单机构单校区/多教室场景设计，多校区作为扩展；
- 智能排课采用规则冲突检测，不追求全局最优算法；
- 系统采用单体应用架构，暂不拆分微服务；
- 统计指标以系统内业务数据为来源，允许毕业设计阶段使用模拟数据。

## 5. 非功能性需求

| 类别 | 需求描述 |
|---|---|
| 性能 | 常用列表分页查询；课表、看板等高频数据可缓存或预统计；普通接口响应满足日常交互 |
| 安全性 | 密码加密存储；JWT 鉴权；接口按角色权限控制；同角色不同账号之间需做数据行级隔离（如家长仅能访问自己绑定学员的数据，教师仅能访问自己或代课范围内课次的数据）；敏感操作记录日志 |
| 数据一致性 | 报名缴费、课时增加、课时扣减、退费、薪资结算使用事务控制 |
| 可用性 | 排课冲突、课时不足、无权操作等异常返回明确友好提示 |
| 可维护性 | 后端按业务模块分包，移动端与管理后台按终端和角色页面组织，接口和数据库文档化 |
| 可扩展性 | uni-app 可发布为微信小程序/H5/App，并支持后续扩展、短信通知、真实支付、多校区等能力 |
| 兼容性 | 家长端和教师端采用 uni-app 移动端实现，适配 H5/微信小程序/App；教务端、财务端和超级管理员端采用 PC 浏览器管理后台 |

## 6. 数据需求

核心业务实体包括：用户、角色、学员、家长学员关系、课程、班级、班级学员关系、教室、课次、教室预约、报名申请、考勤、作业、学情记录、课时账户、课时流水、收费记录、退费记录、薪资规则、教师薪资、考级项目、考级报名、通知公告、操作日志和统计快照。

详细字段设计见 `05-详细设计说明书.md` 和 `10-数据库规范.md`。

## 7. 外部接口需求

| 接口 | 用途 | 备注 |
|---|---|---|

# 核心算法设计文档

> **版本状态**：v1.0 正式版，已与实际代码和测试结果核对，验收日期 2026-07-19。

## 1. 设计目标

本项目不追求复杂机器学习算法，而是围绕培训机构真实教务场景设计可解释、可实现、可测试的业务规则算法：

- 智能排课与冲突检测；
- 课堂考勤后的课时自动扣减；
- 退费金额计算与上限校验；
- 教师月度薪资自动核算；
- 招生、到课率、课时消耗、营收、教师工作量等统计指标。

## 2. 排课冲突检测算法

### 2.1 输入输出

输入：班级ID、教师ID、教室ID、日期、开始时间、结束时间。

输出：是否可排课；若不可排课，返回冲突类型和冲突课次。

### 2.2 时间交叉判断

两个时间段 `[start1, end1)` 与 `[start2, end2)` 存在交叉，当且仅当：

```
start1 < end2 AND end1 > start2
```

### 2.3 检测维度

排课冲突检测覆盖五个时间交叉维度，另有一项非时间交叉的容量校验：

| 维度 | 检测说明 |
|---|---|
| 教师冲突 | 同一教师同一时间不能教授两节未取消课程 |
| 教室冲突 | 同一教室同一时间不能安排两节课（`schedule_lesson` 常规排课占用） |
| 教室预约冲突 | 同一教室同一时间不能与 `room_booking` 非常规占用（考试、教研活动等）冲突 |
| 班级冲突 | 同一班级同一时间不能安排两节未取消课程 |
| 学员冲突 | 同一学员（通过 class_student 关联多个班级）同一时间不能被排入两节未取消课程 |

| 非时间交叉校验 | 说明 |
|---|---|
| 容量校验 | 教室容量应大于等于班级 `max_student_count`（班级设计容量上限，而非当前实际人数，避免后续报名满员后教室不够坐） |

> 上述教师/教室/教室预约/班级/学员五类冲突判断均复用 §2.2 的时间交叉公式；`schedule_lesson` 相关查询范围限定为 `status IN (1,2)`（待上课、已完成），已取消（3）与已调课（4）的旧课次不参与判断，否则调课后空出的时间段会被误判为仍有冲突（详见 §2.4 伪代码）。与 `05-详细设计说明书.md` §5.1 的"五个维度"表述保持一致。

### 2.4 伪代码

```
function checkConflict(classId, teacherId, classroomId, date, start, end):
    conflicts = []
    ACTIVE_STATUS = [1, 2]  // 待上课、已完成；已取消(3)/已调课(4)不参与冲突判断
    if exists lesson where teacherId same and date same and status in ACTIVE_STATUS and timeOverlap(start, end):
        conflicts.add("教师时间冲突")
    if exists lesson where classroomId same and date same and status in ACTIVE_STATUS and timeOverlap(start, end):
        conflicts.add("教室时间冲突")
    if exists booking where classroomId same and date same and timeOverlap(start, end):
        conflicts.add("教室预约冲突")
    if exists lesson where classId same and date same and status in ACTIVE_STATUS and timeOverlap(start, end):
        conflicts.add("班级时间冲突")
    studentIds = findStudentIdsByClass(classId)
    if exists lesson l where l.classId in classesOf(studentIds) and l.classId != classId
            and date same and status in ACTIVE_STATUS and timeOverlap(start, end):
        conflicts.add("学员时间冲突")
    if classroom.capacity < classGroup.maxStudentCount:
        conflicts.add("教室容量不足")
    return conflicts
```


## 3. 批量排课算法

```
输入：班级、教师、教室、日期范围、星期集合、开始时间、结束时间
1. 在数据库事务内锁定 `schedule_lock` 固定行，串行化跨实例智能排课请求；
2. 遍历日期范围；
3. 若日期星期在星期集合中，则生成候选课次；
4. 对每个候选课次执行冲突检测；
5. 若存在冲突，汇总冲突并返回；
6. 若全部无冲突，批量保存课次并提交事务，随后自动释放行锁。
```

毕业设计阶段建议采用“全部通过才保存”的策略，避免部分课次成功、部分失败导致教务难以理解。

## 4. 课时自动扣减算法

### 4.1 扣减规则

| 考勤状态 | 默认扣课时 | 可配置性 |
|---|---|---|
| 到课 | 1 | 固定扣减；余额不足 1 时允许扣至 0 并标记欠费（见 §4.2），因到课是刚性事实，不能像请假一样跳过 |
| 迟到 | 1 | 可配置为固定扣减，或按迟到时长折算部分课时 |
| 请假 | 0 | 可配置为扣/不扣；机构如需防止滥用可另行配置请假次数上限或提前通知时限，不属于本算法强制范围 |
| 缺勤 | 1 | 可配置为扣/不扣 |

### 4.2 伪代码

```
function deductLesson(studentId, courseId, lessonId, attendanceStatus):
    existing = findAttendance(lessonId, studentId)
    if existing != null:
        // 教师修改了已提交的考勤状态：先回冲原扣减，再按新状态重新计算，整体仍在同一事务
        if existing.deductLessons > 0:
            reverseAmount = existing.deductLessons
            account0 = findLessonAccount(studentId, courseId)  // FOR UPDATE + version 乐观锁
            update account0.remainingLessons = account0.remainingLessons + reverseAmount, version = version + 1
            insert lesson_flow(accountId, studentId, lessonId, sourceType=4, +reverseAmount, "考勤状态变更回冲")

    deduct = getDeductAmount(attendanceStatus)
    if deduct == 0:
        upsert attendance(lessonId, studentId, attendanceStatus, deductLessons=0)
        return

    account = findLessonAccount(studentId, courseId)  // SELECT ... FOR UPDATE，或用 version 乐观锁重试
    if account.remainingLessons <= 0:
        if attendanceStatus == ARRIVED:
            throw "课时余额为0，请先完成续费"
        else:
            deduct = 0  // 迟到/缺勤在余额为0时不再继续扣减，仅记录考勤状态
    else if account.remainingLessons < deduct and attendanceStatus == ARRIVED:
        deduct = account.remainingLessons  // 到课允许扣至0，差额记为欠费，不扣成负数
    else if account.remainingLessons < deduct:
        throw "课时不足"

    before = account.remainingLessons
    after = before - deduct
    update account.remainingLessons = after, version = version + 1 WHERE id = account.id AND version = account.version
    upsert attendance(lessonId, studentId, attendanceStatus, deductLessons=deduct)
    insert lesson_flow(accountId, studentId, lessonId, sourceType=3, sourceId=attendance.id, -deduct, before, after)
```


### 4.3 一致性要求

考勤记录、账户余额更新和课时流水写入必须处于同一数据库事务中。若任一步失败，整体回滚。

## 5. 退费金额计算算法

### 5.1 输入输出

输入：`enrollment_id`（退费针对的报名记录）。

输出：建议退费金额、是否超过可退上限。

### 5.2 计算公式与伪代码

```
可退课时 = lesson_account.remaining_lessons
课时单价 = course.price / course.total_lessons
建议退费金额 = 可退课时 × 课时单价 - 违约金（可配置，默认0）

function calculateRefund(enrollmentId):
    paidTotal = sum(payment_record.amount where enrollment_id = enrollmentId)
    refundedTotal = sum(refund_record.amount where enrollment_id = enrollmentId and status = 已通过)
    refundCap = paidTotal - refundedTotal
    suggested = remainingLessons * unitPrice - penalty
    if suggested > refundCap:
        return { amount: refundCap, warning: "建议退费金额超过可退上限，已按上限计算，请人工核实是否存在降价/优惠导致的偏差" }
    return { amount: suggested, warning: null }
```

退费上限校验（`suggested` 不得超过该 `enrollment` 累计已缴费金额减去累计已退费金额）是本算法的强制约束，不属于可选规则。

## 6. 教师薪资自动核算算法

### 6.1 数据来源

- `schedule_lesson`：状态为"已完成"的课次；
- `attendance`：课次下的有效考勤记录（用于校验该课次确有考勤登记，未登记考勤的课次不计入薪资，避免文字口径与实现脱节）；
- `salary_rule`：教师/课程课时单价和代课系数；
- `teacher_salary`：月度结算单。

### 6.2 代课定义与系数说明

某课次的主讲教师（`class_group.teacher_id`）请假或缺席时，由另一教师临时顶替授课，该课次记入顶替教师的"代课课时"而非"主讲课时"。`substitute_rate`（代课系数）默认建议取值范围 (0, 1]，即代课工资按主讲课时单价打折结算；机构如需以加成方式鼓励救场，可配置大于 1 的系数，取值由机构在 `salary_rule` 中自行维护。

### 6.3 计算公式

```
基础课时工资 = 主讲课时 × 课时单价
代课工资 = 代课课时 × 课时单价 × 代课系数
应发工资 = 基础课时工资 + 代课工资 + 奖金补贴 - 扣款
```

### 6.4 伪代码

```
function calculateSalary(teacherId, month):
    snapshotTime = now()
    lessons = findCompletedLessons(teacherId, month, before=snapshotTime)
    validLessons = filter(lessons, l -> existsAttendance(l.id))  // 与 §6.1 保持一致：无考勤登记的课次不计入薪资
    mainHours = sum hours of validLessons where teacherId is main teacher
    substituteHours = sum hours of validLessons where teacherId is substitute teacher
    rules = findSalaryRules(teacherId)
    baseAmount = sum(mainHoursByCourse * unitPrice)
    substituteAmount = sum(substituteHoursByCourse * unitPrice * substituteRate)
    total = baseAmount + substituteAmount + bonus - deduction
    save teacher_salary(calcSnapshotTime = snapshotTime, ...)
```

### 6.5 防重复结算

同一教师同一月份只能存在一张有效结算单（`teacher_id + salary_month` 唯一约束）。若结算单已确认（status=2），不允许直接覆盖。

### 6.6 确认后课次/考勤变更的处理

若 `calc_snapshot_time` 之前统计过的课次或考勤，在薪资单确认后被追溯修改，不重新计算并覆盖 `teacher_salary.total_amount`，而是：

```
1. 按变更前后课时差额计算调整金额；
2. 写入 salary_adjustment(teacher_salary_id, adjust_amount, reason, operator_id)；
3. 教师实发金额 = teacher_salary.total_amount + sum(该单下全部 salary_adjustment.adjust_amount)；
4. 需要整单作废时，将 teacher_salary.status 置为"已撤销"(4)，并重新执行 §6.4 生成新单。
```

## 7. 统计指标计算

| 指标 | 计算口径 | 数据来源 |
|---|---|---|
| 招生人数 | 统计周期内审核通过报名人数 | enrollment |
| 到课率 | 到课人数 / 应到人数 | attendance、schedule_lesson |
| 课时消耗 | 统计周期内课时流水中消耗课时总和 | lesson_flow |
| 班级活跃度 | 到课率、作业提交、课次完成综合评分 | attendance、homework |
| 教师工作量 | 教师完成课时 + 代课课时 | schedule_lesson |
| 营收 | 收费金额 - 退费金额 | payment_record、refund_record |
| 课程盈利 | 课程收入 - 对应教师薪资成本 | payment_record、teacher_salary |
| 学员流失率 | 退班或长期未续费学员 / 总学员 | student、refund_record、lesson_account |

## 8. 报表导出规则

报表导出应复用统计查询结果，避免前端自行计算。导出内容包括：收费台账、课时流水、教师薪资、营收统计、到课率统计。

## 9. 复杂度分析

| 算法 | 时间复杂度 | 优化方式 |
|---|---|---|
| 单课次冲突检测 | O(k)，k 为同日相关课次数 | 使用 teacher/date、classroom/date、class/date、student/date 索引 |
| 批量排课 | O(n*k)，n 为候选课次数 | 批量查询同范围课次后内存检测 |
| 课时扣减 | O(1) | student_id + course_id 唯一索引 + 乐观锁重试 |
| 退费金额计算 | O(1) | enrollment_id 上的 payment_record/refund_record 索引聚合 |
| 薪资核算 | O(m)，m 为教师当月课次数 | teacher_id + lesson_date 索引 |
| 统计聚合 | O(n) | 汇总表/快照表预计算 |

## 10. 答辩说明建议

答辩时可重点说明：

1. 排课冲突检测如何覆盖教师、教室、班级、学员和容量五个维度；
2. 课时账户与课时流水如何通过乐观锁和事务保证并发安全、可追溯；
3. 退费金额如何在计算建议值的同时校验已缴费上限；
4. 薪资结算如何由课次和考勤数据自动生成，并通过调整记录处理确认后的变更；
5. 数据统计如何从业务明细聚合到管理看板。

## 二、Critical 问题（影响功能正确性和数据安全性）

### C1. 课时乐观锁机制不完整 — ✅ 已于 2026-07-13 修复
> **修复内容**：`LessonAccount.java` line 27 已添加 `@Version` 注解；`MybatisPlusConfig.java` line 19 已注册 `OptimisticLockerInnerInterceptor`。乐观锁 CAS 机制现已生效。

| 项目 | 详情 |
|---|---|
| **文件** | `LessonAccount.java`（第27行）、`MybatisPlusConfig.java`（第12-17行） |
| **文档依据** | `docs/10-数据库规范.md` §3.5 明确要求 `UPDATE ... WHERE id = ? AND version = ?` 做 CAS |
| **现状** | `version` 字段未标注 `@Version`；`MybatisPlusConfig` 未注册 `OptimisticLockerInnerInterceptor` |
| **后果** | AttendanceServiceImpl 中 `account.setVersion(account.getVersion() + 1)` 只是手动递增版本号，底层 SQL 不包含 `WHERE version = oldVersion`，并发场景下两个线程同时扣减会读到相同 version 并都更新成功，**乐观锁完全无效** |
| **修复建议** | ①在 `LessonAccount.version` 添加 `@Version` 注解；②在 `MybatisPlusConfig.mybatisPlusInterceptor()` 中 `addInnerInterceptor(new OptimisticLockerInnerInterceptor())` |

```java
// LessonAccount.java 修复
@Version
private Integer version;

// MybatisPlusConfig.java 修复
interceptor.addInnerInterceptor(new OptimisticLockerInnerInterceptor());
```

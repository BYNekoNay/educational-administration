# 总  结

本文完成了面向艺术培训机构的全流程教务管理平台的设计与实现。系统采用 Vue 3、uni-app、Spring Boot 与 MySQL 等技术栈，覆盖招生报名、课程班级、智能排课与调课、课堂考勤、课时自动扣减、收费退费、教师薪资自动核算、学情考级与运营数据统计的完整业务闭环，支持学员家长、授课教师、教务管理员、财务管理员与超级管理员五类角色协同工作，满足了艺术培训机构数字化教务管理的实际需求。系统在完成功能开发与分层测试后，已通过容器化方式完成生产环境部署并稳定运行，实现了从需求分析、设计实现、测试验收到生产上线的完整交付。

在系统设计与实现过程中，主要解决了以下几方面问题：其一，针对移动端报名场景的多接口串行请求与决策数据不一致问题，设计了"报名决策快照 + If-Match 版本校验"的一致性方案；其二，针对教务排课的易用性问题，实现了大课表拖拽快速调课，并通过"状态 + 旧时间"复合乐观条件解决了同状态并发编辑相互覆盖的问题；其三，针对教师薪资人工核算易错问题，建立了按课程薪资规则自动核算并配合状态机与并发控制的核算体系；其四，针对机构运营"只看历史、难防流失"的问题，实现了可解释的多因子流失预警引擎，将统计升级为决策；其五，引入 Flyway 版本化迁移、加密备份恢复、发布门禁与业务可观测性等手段，提升了系统的可靠性与可维护性。

同时，系统仍存在一些不足，也为后续改进指明了方向。首先，在功能层面，当前支付与短信通知为模拟实现，尚未接入真实支付网关与短信服务商；后续计划以适配器方式接入第三方支付网关与短信服务商，复用系统既有的通知外发通道抽象，使缴费与提醒由模拟转为真实投递。其次，在性能与架构层面，系统当前为单机部署，报名决策快照以 5 分钟 TTL 缓存在单机内存中，在多实例部署时无法共享；后续计划将快照缓存迁移至 Redis 分布式缓存，并配合共享并发控制支撑后端多实例水平扩展。最后，在智能化层面，流失预警当前为可解释的多因子规则打分而非机器学习模型；后续可基于系统持续积累的报名、考勤、课时与退费数据，在规则打分的基础上引入机器学习模型，实现更精细的流失预测，同时保留现有规则作为可解释的兜底。上述不足将作为后续改进方向，在保证系统稳定运行的前提下逐步完善。

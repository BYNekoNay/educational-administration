# 2  相关技术介绍

本系统采用前后端分离架构，前端划分为管理后台与移动端两个工程，后端以 Spring Boot 提供统一业务接口。本章按照"本系统选用某项技术用于何种场景、因其具备何种特性"的选型逻辑，依次介绍各关键技术及其在系统中的具体作用，并说明相应的选型理由。

## 2.1  前端框架 Vue 3 与 Element Plus

本系统选用 Vue 3 构建管理后台，主要用于课程、排课、财务等数据密集型页面的呈现与交互。Vue 3 作为渐进式前端框架，其组合式 API（Composition API）与响应式数据模型更适用于本系统横跨教务、财务多业务域时的复杂状态组织与逻辑复用。以排课大课表与薪资核算页面为例，单个页面需要同时管理课次、教师、教室、金额等多组相互联动的状态，组合式 API 配合 TypeScript 可将这些联动逻辑按功能内聚为可复用的组合函数，显著提升页面的可维护性。配合 Vite 5 开发服务器，开发阶段可获得模块热更新与快速构建体验，缩短调试反馈周期。Vite 在生产构建阶段通过依赖预打包与按需编译显著提升构建速度，其产物经压缩后便于以静态资源方式由 Web 容器托管。

在此基础上，本系统选用 Element Plus 作为桌面端组件库。Element Plus 提供的表格、表单、弹窗、分页、日期选择等企业级组件与中后台交互模式高度契合，本系统的课程管理、排课、财务等数据密集型页面正是依托其表格的排序筛选、表单的校验联动、分页与日期选择等能力快速搭建而成。管理后台整体采用 Vue 3 + Element Plus + Pinia + TypeScript 的组合：Pinia 负责登录态、角色权限等全局状态的统一管理，页面依据角色动态渲染可操作入口，实现前后端双重的权限控制；TypeScript 则为课程、课次、薪资等复杂数据模型提供静态类型保障，降低多业务域下的维护成本。在工程组织上，管理后台按功能域拆分页面与通用组件，排课、财务等模块复用同一套表格与表单封装，既保证交互一致性，也减少了重复开发。

## 2.2  跨平台框架 uni-app

本系统选用 uni-app 实现移动端家长端与教师端。移动端使用者以学员家长与授课教师为主，其场景集中在课表查看、报名缴费、考勤打卡与消息接收等高频轻量操作，对多端覆盖能力有较强需求。uni-app 以一套 Vue 语法代码即可编译运行到 H5、微信小程序与 Android/iOS App 等多个平台，能够显著降低多端重复开发成本，使机构一次投入即可同时服务网页端与小程序端用户。

本系统移动端基于 uni-app 与 uView Plus 组件库实现家长端与教师端页面。由于 uni-app 使用 Vue 语法，与管理后台技术栈保持一致，降低了团队的学习与维护门槛。更重要的是，家长端与教师端的业务规则统一由后端接口提供，两端口径一致，避免了业务规则在移动端重复实现而导致的数据口径不一致。为保证移动端核心展示逻辑的可回归性，报名决策快照、课表摘要、请假状态文案、未读角标等纯逻辑被抽离为独立模块并配有单元测试，使移动端质量同样可度量。在工程实践上，移动端与小程序产物通过统一的构建脚本产出，配合后端既有的通知外发通道，使家长与教师能够在不同终端获得一致的教务信息推送。

## 2.3  后端框架 Spring Boot 与 MyBatis-Plus

本系统选用 Spring Boot 3.2.5 作为后端开发框架，主要因其"约定优于配置"的理念可通过自动装配与起步依赖大幅简化工程搭建，使团队能将精力集中于业务逻辑本身。其内置嵌入式 Web 容器支持构建可独立运行的 JAR 包，便于本系统以容器镜像方式进行生产化部署；Spring Boot 3.2.5 基于 JDK 17，生态成熟，可提供定时任务、事件机制以及 Actuator 健康检查与指标暴露等能力。本系统的流失预警月度统计依托定时任务周期性触发，发布健康探针与业务可观测性则建立在 Actuator 与指标暴露能力之上。

在持久层，本系统选用 MyBatis-Plus 3.5.7。它在保留 MyBatis 手写 SQL 灵活性的同时，提供通用 CRUD、逻辑删除、乐观锁、分页插件等开箱即用的能力，可有效减少数据访问层样板代码。逻辑删除被用于用户等核心表，使数据删除转为标记而非物理移除；分页插件统一了各列表查询的分页行为；乐观锁机制则支撑课时账户、退费审核与薪资流转等关键数据的并发安全，使"读-改-写"型并发操作获得统一的并发控制手段，避免了课时被重复扣减、退费被并发触及等问题。在分层结构方面，后端遵循 controller、service、mapper 的分层约定，配合统一异常处理与参数校验，使业务异常可被集中转化为面向前端的友好提示，提升了接口的健壮性与一致性。

## 2.4  数据库 MySQL 与版本化迁移 Flyway

本系统选用 MySQL 8.0 存储业务数据。MySQL 支持 InnoDB 事务引擎与行级锁，具备良好的事务一致性与并发控制能力，契合资深教务业务中课时扣减、退费回冲与薪资结算等操作对数据一致性的严格要求。本系统共设计 37 张表，覆盖用户权限、学员课程、排课调课、考勤学情、课时流水、财务薪资、考级通知与运营管理八大业务域，各业务域之间通过外键与关联表形成统一的业务数据模型。在索引策略上，课程、班级、课次等高频查询场景建立组合索引以加速列表与关联查询；退费记录表通过数据库生成列与唯一索引实现"同一报名仅允许一条待审核退费"的约束，从数据库层兜底并发安全。

为消除开发、测试与生产环境之间的数据库结构差异，本系统引入 Flyway 进行版本化数据库迁移：结构变更以编号迁移脚本统一管理，生产环境启动时按序自动执行，从而保证各环境数据库状态一致。迁移脚本具备幂等性，支持存量数据库平滑升级；系统以建表脚本建立基线版本，再按序执行增量迁移脚本，其中 V6 用于高价值查询索引、V7 用于单待审核退费约束、V8 用于流失预警跟进表。这种版本化手段使数据库结构的演进可审计、可回放，是系统可维护性与可靠性的重要基础。在事务控制上，课时扣减、退费回冲与薪资结算等涉及多表写入的操作均在数据库事务内完成，配合行级锁保证中间状态对外不可见，从而在并发场景下维持数据的最终一致。

## 2.5  认证与安全技术 JWT

本系统选用 JWT（JSON Web Token）作为身份认证方案。由于系统采用前后端分离架构，并区分管理后台与移动端两类客户端，JWT 作为无状态认证方案尤为合适：服务端在登录成功后签发包含用户标识与角色信息的签名令牌，客户端在后续请求中携带该令牌，服务端验签后即可确认身份，天然适配本系统的多端场景，无需在服务端维护会话状态，也便于系统在容器化多实例环境下水平扩展。

本系统使用 HMAC-SHA256 算法对 JWT 进行签名，通过自定义拦截器统一完成令牌校验与基于角色的接口鉴权。接口以注解声明角色要求，五类角色（学员家长、授课教师、教务管理员、财务管理员、超级管理员）的权限被严格隔离，跨角色的非法访问在接口层即被拦截。登录失败、令牌过期与用户被禁用等场景下，系统均正确拒绝请求，从而从机制上杜绝越权数据访问。在令牌生命周期管理上，系统对令牌设置合理的有效期，并在关键操作前重新校验用户状态，确保被禁用的账号无法凭借已签发令牌继续访问。

## 2.6  数据可视化与报表技术

本系统选用 ECharts 与 Apache POI 支撑运营看板的可视化呈现与报表导出。ECharts 是基于 JavaScript 的开源可视化图表库，提供折线图、柱状图、饼图等丰富图表类型。本系统使用其在运营数据看板中呈现月度课时趋势、营收趋势与到课率趋势等统计图表，使管理者能够直观掌握机构招生、到课与营收的真实状况，将沉淀的业务数据转化为可决策的运营洞察。

Apache POI 是 Java 处理 Office 文档的开源类库。本系统基于其 SXSSF 流式写入组件实现收费台账、课时消耗、薪资结算与流失预警名单等报表的 Excel 导出。SXSSF 采用流式写入方式，在大数据量报表导出场景下能有效控制内存占用，避免一次性加载全部数据导致的内存压力。两者分别覆盖了"看板可视化"与"离线报表"两类运营数据消费需求。运营看板接口按角色隔离，财务等只读角色可查看统计结果但不能执行管理操作，避免运营数据被越权改写，共同支撑机构的运营分析工作。

## 2.7  本章小结

本章围绕系统的技术选型展开介绍，按照实际应用场景说明了各项关键技术的选型理由。前端以 Vue 3 与 Element Plus 构建数据密集型管理后台，以 uni-app 实现跨平台移动端；后端以 Spring Boot 与 MyBatis-Plus 提供统一、可靠的业务接口；数据层以 MySQL 配合 Flyway 版本化迁移保障一致性与可演进性；安全层以 JWT 实现多端无状态认证与角色隔离；运营层以 ECharts 与 Apache POI 分别支撑可视化看板与报表导出。上述技术共同构成了本系统从前端交互、后端服务到数据存储与运营分析的完整技术底座，为后续需求分析、总体设计与详细实现提供了支撑。

# 5  系统测试

## 5.1 测试环境与测试方法

本系统测试覆盖单元测试、组件测试、接口测试与浏览器验收四个层次。测试环境如表 5.1 所示。

表 5.1  测试环境

| 项目 | 环境 |
|------|------|
| 操作系统 | Windows 11（开发）、Ubuntu 26.04（部署） |
| 后端运行环境 | JDK 17、Spring Boot 3.2.5 内置 Tomcat |
| 数据库 | MySQL 8.0（生产）；H2（测试内存库） |
| 前端 | Node.js 22、Vite 5 |
| 单元测试框架 | JUnit 5 + Mockito + AssertJ（后端）；Vitest + Vue Test Utils（前端） |

系统采用分层测试策略：后端对 20 个核心业务 Service 类实现全覆盖的 Mockito 单元测试，并引入 H2 内存数据库执行 Spring 上下文加载冒烟测试；管理后台对各页面组件与纯逻辑模块（排课拖拽逻辑、流失预警面板等）进行组件测试；移动端对报名决策快照等核心纯逻辑进行单元测试；此外通过自动化接口测试覆盖五类角色的授权端点与越权拒绝场景，并通过浏览器自动化执行主要业务流验收。

在分层测试之外，系统在首次生产上线后组织了一轮面向真实部署环境的浏览器验收测试，用于验证五类角色在实际部署形态下的主要业务流程。该轮测试共设计 69 条用例，按优先级分为 P0（核心主流程）33 条、P1（重要功能）32 条、P2（增强项）4 条，覆盖登录与权限隔离、超级管理员、教务管理员、财务管理员、授课教师、学员家长、越权与安全以及移动端专项八个模块。测试方法遵循两条硬性约束：其一，测试手段限定为界面操作（打开页面、点击、输入、切换、拖拽、上传、截图），不允许以调用后端接口或直连数据库作为获取预期结果的手段，从而模拟真实用户的使用路径；其二，断言以视觉识别为主、DOM 定位为辅，判定结论以截图中可读到的文字、颜色、数值与元素可见性为准，而非依赖接口返回值。最终 69 条用例全部通过，覆盖率达 100%。为交叉验证写操作的真实效果，测试还通过数据库对新增缴费记录、课时流水、退费回滚与课时账户最终态等记录逐项对账，结果与界面表现完全吻合，证明系统的乐观并发控制与账实一致性符合预期。

## 5.3 非功能性测试

### 5.3.1 并发一致性测试

针对系统核心并发操作设计并发测试，重点验证乐观并发控制的有效性。测试覆盖快速调课"同状态并发编辑"场景（T09）：由于快速调课不翻转状态字段，仅凭状态条件无法拦截同状态并发，系统在乐观更新条件中追加旧时间条件，使并发第二笔更新失败并返回 409。回归测试还捕获更新条件参数，防止将来被改回仅有"id + 状态"的弱并发保护。退费审核、薪资确认/发放/撤销、课时扣减等操作同样以乐观更新行数校验保证并发正确性。

### 5.3.2 安全测试

系统安全性测试覆盖以下方面：其一，越权访问防护——通过自动化接口测试验证五类角色共 32 个授权端点可用、6 类未授权/越权请求被正确拒绝（匿名用户、跨角色访问用户管理/机构配置/操作日志等），角色间数据不可越权访问；其二，身份认证安全——接口统一要求 JWT 令牌，登录失败、令牌过期与用户被禁用场景下均正确拒绝；其三，输入与上传安全——上传文件同时校验扩展名、Content-Type 与文件头魔数签名，防止伪装文件上传；其四，生产配置校验——系统在生产环境启动时校验数据库密码、JWT 密钥强度与 CORS 来源白名单，拒绝默认弱配置启动。

### 5.3.3 可靠性测试

可靠性方面：其一，数据库结构一致性——引入 Flyway 版本化迁移后，迁移脚本具备幂等性，支持存量数据库平滑升级，并通过高价值数据不变量检查（孤儿收费/退费记录）作为部署硬门禁；其二，数据可恢复性——建立 MySQL 与上传附件的加密备份与恢复演练机制，可验证备份可用；其三，发布可验证性——部署流水线设置后端与前端测试门禁、登录接口冒烟探测与容器健康检查，失败即阻止发布；其四，系统可观测性——提供健康/就绪探针、业务指标与请求关联日志，便于线上问题定位。

## 5.4 测试结论

系统测试结果汇总如表 5.6 所示。

表 5.6  测试结果汇总

| 测试层次 | 范围 | 数量 | 结果 |
|---------|------|:---:|:---:|
| 后端单元测试 | 20 个核心业务 Service 全覆盖 | 464 | 全部通过 |
| 管理后台组件测试 | 26 个测试文件 | 118 | 全部通过 |
| 移动端逻辑测试 | 报名决策快照、课表摘要、请假状态、未读角标等纯逻辑 | 25 | 全部通过 |
| 接口与权限测试 | 五角色授权矩阵 | 38（32 授权 + 6 越权） | 全部通过 |
| 浏览器验收 | 五角色主要业务流程（浏览器自动化 + 视觉断言） | 69 | 全部通过 |

测试结果表明：系统功能完整覆盖任务书要求，报名审核、排课调课、考勤课时扣减、薪资核算与流失预警等核心业务正确；快速调课、退费、薪资流转等并发路径防护有效；五类角色权限隔离正确，越权访问被拒绝；系统可靠性机制（迁移、备份、发布门禁、可观测性）完备。系统达到可交付运行状态，并已在生产环境完成容器化部署上线、持续稳定运行，实现了从开发、测试到上线运行的完整交付。

## 5.5 本章小结

本章说明了系统的分层测试环境与策略，并从功能测试、并发一致性测试、安全测试与可靠性测试四个方面对系统进行了验证。功能测试覆盖报名缴费、排课调课、考勤课时与流失预警等核心业务，代表性用例表明主要流程正确；并发一致性测试证实快速调课、退费审核、薪资流转等并发路径的乐观并发控制有效；安全测试证实五类角色权限隔离正确、越权访问被拒绝、认证与上传安全可控、生产配置校验到位；可靠性测试证实数据库迁移、加密备份、发布门禁与业务可观测性等机制完备。最终汇总表明，后端 464 个单元测试、管理端 118 个与移动端 25 个测试全部通过，五角色授权矩阵（32 授权 + 6 越权）与 69 条浏览器自动化验收用例均通过，系统达到可交付并已完成容器化生产部署上线。

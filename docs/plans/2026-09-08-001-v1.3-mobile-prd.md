## 〇、一句话结论

**v1.3 补的不是"页面没有的功能"，而是"旅程断了的口子"——核对我方发现：任务书要求的家长/教师功能在移动端其实已基本落地，真实缺口集中在四类：(1) 教师端没有"学员请假审批"入口（后端接口已备但无人消费）；(2) 课表主 Tab 是"永远显示无课"的空壳（只跳转不展示）；(3) 教师课表只显示裸 ID 不显示课程/班级名，与家长端课表富信息明显不对等；(4) 消息中心无未读角标、家长学情只显示"课次ID"上下文残缺。本轮以"低成本补齐这些对等度/闭环缺口 + 补测试"为目标。**

---

## 一、与上一轮及题目的关系

- 上一轮 v1.2 的主战场是**管理后台**（拖拽调课、流失预警、SSE/外发通道），mobile-uniapp 除通知呈现外基本未动；用户本轮明确方向为**移动端补齐、提升三端均衡度**。
- 任务书要求家长/教师两大移动角色具备：家长（报名缴费、课表、学情、课时、消息）；教师（排班课表、课堂考勤、学情管理、课时统计）。**v1.2 合规核对已逐条确认"有实现"**，本轮需把移动端上"能看见/能操作"的程度补齐到与后台同一水平。
- 特别提醒：经实际核对，**团队预判的部分缺口并不存在**（见 §三"伪缺口澄清"），避免架构师重复建设。

## 四、产品目标（3 条，正交）

1. **闭环补齐**：让"家长请假→教师审批→家长可见结果"整条旅程可在移动端完成，不再必须切回管理后台（提升家长/教师两端的操作均衡度）。
2. **信息对等**：同一份课表/学情数据，在移动端展示的信息丰富度与后台一致——修掉"教师课表裸 ID""家长学情课次 ID 无上下文"这类信息残缺，让移动端可作为日常主入口。
3. **入口真实**：把 tabBar 主入口（课表 Tab、消息 Tab）从"假空壳/纯跳转"升级为真实内容摘要+未读提示，降低每天打开 App 却看到空态的落差感。

## 五、用户故事

1. **作为教师，我希望在我的移动端看到本班学员提交的请假申请并能"通过/驳回"（可写备注），以便家长请假后我当场处理，不需要教务代劳。**（P0-1）
2. **作为家长，我希望我提交的请假在教师处理后立即显示"已通过/已驳回及原因"，以便确认孩子当天是否被准假、避免误以为要上课。**（P0-1 关联验收）
3. **作为家长/教师，我希望打开底部"课表"Tab 直接看到今天（及未来数天）的真实课次摘要，而不是永远显示"今天没有课程安排"的空壳。**（P0-2）
4. **作为教师，我希望我的课表显示课程名/班级名/上课时间/状态并按日期排列，而不是只看到班级 ID 和教室 ID。**（P1-1）
5. **作为家长/教师，我希望消息入口能看到未读数量、及时刷新最新消息，以便不漏掉调课/上课/公告提醒。**（P1-2）

## 七、UI 设计要点（草案）

1. **教师"请假审批"入口与页面**
   - 入口：教师首页 cell 组新增"请假审批"（徽标显示待处理数，可选）或并入"课堂考勤"页内 Tab。
   - 列表卡片：学员姓名 + 请假日期 + 原因（截断）+ 状态标签（待处理/已通过/已驳回）。
   - 操作：待处理项提供"通过 / 驳回"两按钮，驳回时弹输入备注（≤200 字），复用家长请假记录 UI 视觉风格。
2. **课表 Tab（pages/schedule/index.vue）**
   - 上半区"今日课次"卡片列表（时间轴 + 课程/班级 + 状态色块）；下半区"未来 N 天"摘要 + "查看完整课表"入口。
   - 家长与教师共用页，按当前角色渲染各自数据源；家长保留学员切换。
3. **教师课表（teacher/schedule.vue）**
   - 从"平铺列表"改"按日期分组"，每组 header 为日期+星期，课程卡显示课程名/班级名/时间/状态；今日组高亮；保持与家长端课表一致的暖色卡片体系。
4. **消息 Tab**
   - 首页/消息图标用 `uni.setTabBarBadge` 或首页卡片显示未读数；notices 页顶部加"未读/全部"分段或未读红点计数。

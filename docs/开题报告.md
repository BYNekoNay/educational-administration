# 字段 1、本课题的研究意义，国内外研究现状和发展趋势

一、研究意义

艺术培训是素质教育的重要组成部分，涵盖音乐、舞蹈、美术、体育等多种课程形态。与学科类培训相比，艺术培训机构具有更为鲜明的运营特征：课程类型繁多且差异显著，既有单次体验课，也有按学期、按考级或考段阶段划分的长期课程；上课频次高，多以周为单位常态化排课；授课教师多为兼职或外部合作，排班与场地调度复杂；学员以未成年人为主，请假、调课、补课频繁；机构收入依赖课时包销售，课时扣减与教师薪资高度关联又长期依赖人工核算。这些特征相互叠加，使教务管理成为机构日常运营中信息密度最高、最易出错的环节。

传统管理模式下，大量中小型机构仍以电子表格或纸质登记本记录学员信息、课表、考勤与收费，由此产生五类痛点：一是数据分散在多个表格与人员手中，流转依赖人工传递，统计滞后，管理者难以及时掌握招生、到课、营收与流失状况；二是课时多由教务人员按考勤手工扣减，面对多学员、多课程的复杂组合极易误扣漏扣；三是排课依赖经验试行，教师、教室、班级之间的时间冲突难以一次暴露，只能在使用中被动发现；四是教师薪资以课时为基础人工汇总，既慢又易错，且缺乏可追溯明细；五是学员流失具有隐蔽性，等续费明显下滑才被察觉，往往已错失干预窗口。随着规模扩大，手工模式的人力成本与差错成本呈非线性上升，成为制约机构规模化、规范化运营的瓶颈。

教务管理信息化因此具备明确的工程价值：将招生、排课、考勤、课时、财务、学情等环节统一到同一系统，可使流程标准化、数据口径一致化，消除信息孤岛；借助自动化的课时扣减、冲突检测与薪资核算，可显著降低人工差错、提升效率；沉淀的业务数据可支撑运营看板与流失预警，使机构由事后统计转向事前干预。本课题以中小型艺术培训机构为服务对象，研究并实现覆盖上述全流程的教务管理平台，以工程化手段解决实际管理难题，具有明确的现实意义与应用价值。

二、国内外研究现状

（一）国外研究现状

国外相关研究起步较早，与本课题关联最紧密的方向是智能排课、并发一致性与学员流失预测。

智能排课方面，课程表编排本质上是受多重约束的组合优化问题。Han 等人提出遗传算法与动态规划相结合的混合方法求解大学排课问题，并引入贪心策略完成教室分配，在满足多重约束的同时提升了排课质量与教室利用率；Xiang 等人设计了两阶段元启发式算法，先以图着色对课程聚类、再以增强禁忌搜索将课程簇分配至时间段，实验表明其在真实场景下兼顾了效率与解的合理性。

并发一致性方面，Pophali 系统比较了数据库隔离级别以及乐观锁与悲观锁策略在高并发扣减场景下的表现，并给出实施准则，表明乐观锁可在冲突概率较低的场景下避免超扣并提升吞吐。

学员流失预测方面，已有研究普遍将其视为数据挖掘或机器学习问题，并从单一成绩特征扩展到多维行为与社会经济特征。Huynh-Cam 等人利用入学前即可获得的人口学、家庭背景与经济状况信息构建早期预测模型并提取关键影响因子，为早期预警与干预提供依据；Gutierrez-Pachas 等人面向拉丁美洲高等教育场景，综合学术、社会经济与公平三类因素，结合机器学习与生存分析支持辍学决策，说明流失风险可由多源因素共同刻画。这类研究表明，到课行为、参与程度与流失风险之间存在稳定关联，为本系统以到课沉寂度、缺勤倾向等因子刻画流失风险提供了依据。

（二）国内研究现状

国内面向教培机构与教务管理的研究近年持续增多，覆盖排课、冲突检测、可视化、学情分析、薪资核算、移动端与档案管理等多个环节。排课与数据库设计方面，黄玉蕾等人面向高校排课中学生选课需求与教室、教师资源冲突问题，完成了排课系统的需求分析与数据库设计；冲突检测方面，有研究将日程冲突检测抽象为时间区间的重叠检测，并基于区间树实现高效的插入、删除与查询，为排课、排班等场景提供算法支撑。运营可视化方面，刘梦等人将 ECharts 可视化技术应用于数据管理平台，实现多维数据的图表化呈现。学情与预警方面，有研究融合群体与个体行为特征构建成绩预警模型，提升了预警的准确性与前置性。财务与薪资方面，有研究设计了高校新职工工资自动核算系统，完成工资套算、基数确定、扣除计算与补发合计等任务。移动端方面，韦彩仁等人基于 uni-app 开发了信息管理系统的学生端，验证了跨端框架在移动端信息管理中的适用性。系统与档案方面，有研究基于 B/S 架构实现了高校教务管理系统；张浩研究了档案管理数字化系统的设计与实现，为档案信息的规范化存储与检索提供了参考。

综合来看，现有研究多聚焦单一算法点或单一业务环节，或集中于某一端的某项功能，这类点状成果难以拼装为可用、可靠、可维护的整体系统。其突出短板在于：缺少面向中小型艺术培训机构、覆盖招生、排课、考勤、课时、财务、学情全业务链条的工程化落地系统；缺少以统一数据模型串联各环节并形成业务闭环的设计；也缺少在并发一致性、权限隔离与可维护性等工程质量属性上的系统性保障。

三、发展趋势

综合来看，本领域呈现以下发展趋势。其一，系统形态由单点工具走向全流程一体化平台，各环节共享统一数据模型、协同构成业务闭环。其二，决策能力由事后统计走向事前预警干预，以规则化、可解释模型刻画流失风险是当前较为务实的落地形态，并逐步向学习模型演进。其三，应用形态由单端应用走向多端协同，家长与教师的高频轻量场景落在移动端，重管理场景保留在 Web 后台。其四，并发一致性、权限与数据隔离、可维护性与可观测性等工程质量属性日益成为交付底线。其五，部署形态由单机部署走向容器化与版本化数据库迁移，以支撑可回滚的持续交付。

# 字段 2、主要研究内容

一、研究对象与总体范围

本课题的研究对象是中小型艺术培训机构的教务管理业务，研究范围界定为构建一个覆盖招生、排课、考勤、课时、财务、学情全流程的教务管理平台，把分散于多个表格与人员手中的业务环节统一到同一系统与同一数据模型之中，使业务流程标准化、数据口径一致化，从根本上消除信息孤岛，并把机构的运营数据沉淀为可用于决策的依据。

二、五类角色对应的研究内容

平台面向学员家长、授课教师、教务管理员、财务管理员与超级管理员五类角色。学员家长侧研究在线报名缴费、课表查看、学情查看、课时管理与消息通知，涵盖剩余课时查询、消耗流水查看与到期提醒；授课教师侧研究授课课表与上课提醒、调课申请、课堂考勤、学情管理与课时统计，其中课堂考勤需支持到课、迟到、请假、缺勤四种状态；教务管理员侧研究课程与班级管理、智能排课与冲突检测、学员报名审核与分班转班、考级管理以及教务数据统计；财务管理员侧研究收费与续费、退费审核、教师薪资结算与营收统计报表；超级管理员侧研究人员权限与机构配置、公告管理以及全局运营数据看板。五类角色通过统一的数据模型相互衔接，共同构成覆盖招生至学情的业务闭环。

三、需攻克的关键技术问题

在基础功能实现之上，本课题重点研究四类关键技术问题。一是报名决策的数据一致性问题：多方并发报名时课程名额、时间冲突与报名状态可能被重复读取，拟以报名决策快照配合版本校验，保证报名决策所依据的数据一致。二是排课易用性与并发编辑冲突问题：拟引入教师、教室、教室预约、班级、跨班学员五个时间交叉维度的冲突检测与拖拽快速调课以提升排课易用性，并以复合乐观并发条件防止同一状态下并发编辑相互覆盖。三是薪资核算的正确性与不可篡改性问题：拟构建状态机与并发控制相结合的核算体系，保证已确认的薪资不被覆盖、后续变更以调整记录留痕。四是机构运营决策能力问题：拟以可解释的多因子规则构建学员流失预警，把运营统计由事后结果展示升级为事前的流失干预。

四、研究目标

本课题的最终目标是完成上述功能的开发与分层测试后，以容器化方式部署上线并在生产环境稳定运行，实现从需求分析、设计实现、测试验收到生产上线的完整交付。

# 字段 3、研究思路和方案

一、技术路线

本课题采用前后端分离的 B/S 架构，选型以团队熟悉度、生态成熟度与部署成本为主要依据。前端采用 Vue 3 承载管理后台课程、排课、财务与运营看板等数据密集页面，并借助 ECharts 实现图表可视化；面向家长与教师的高频轻量场景，以基于 Vue 3 生态的跨端框架 uni-app 实现移动端，一套代码可编译为 H5 与微信小程序；后端采用 Spring Boot 3.2.5 与 MyBatis-Plus 3.5.7 提供统一 RESTful 接口，前者内置事务与安全能力，后者便于复杂统计 SQL 表达；数据持久化采用 MySQL 8.0 以支撑课时、财务与薪资等强一致场景，结构变更由 Flyway 版本化迁移管理，避免人工改表造成环境间结构漂移；缓存暂由应用内存承担（Redis 依赖与配置已预留、多实例时启用）；认证采用 JWT 无状态方案并配合基于角色的接口鉴权实现五类角色权限隔离，使各终端共用同一套业务规则。

二、总体架构分层

系统自顶向下划分为五层，各层只依赖其下层。客户端层提供管理后台与移动端两类终端；接口与鉴权层负责请求接入、身份认证与基于角色的权限校验；业务服务层按业务域组织服务模块，承载报名、排课、考勤、课时、财务、薪资与统计等核心规则；数据访问层封装数据库读写与聚合查询；基础设施层提供数据库、缓存、文件存储、迁移工具与可观测性支撑。

三、数据库设计思路

数据库以核心业务实体组织表结构，围绕学员、课程、班级、课次、考勤、课时账户与流水、收费、退费、薪资与通知等实体建表，共设计 37 张数据表，按用户权限、学员课程、排课调课、考勤学情、课时流水、财务薪资、考级通知与运营管理八个业务域组织。关键约束包括：课次归属于班级、班级关联课程、学员经关联表进入班级；课时余额只由流水驱动变化，考勤扣减与流水一一对应，保证课时变动可追溯；以唯一约束限制同一报名仅有一条待审核退费、同一教师同一月份仅有一张有效结算单；高频查询字段建立组合索引。

四、核心算法与规则方案

核心算法以可解释、可实现、可测试为设计原则。自动排课以教师、教室、教室预约、班级、跨班学员五维时间交叉检测为核心，冲突课次即时提示并不予保存；课时自动扣减以考勤状态为输入，到课与迟到按规则扣减、请假经审批后不扣减，考勤记录、余额更新与流水写入处于同一事务，并以版本号乐观锁防止并发覆盖；薪资核算按课次、班级、课程到薪资规则的映射统计当月有效课时并自动计算应发金额，核算记录数据快照时间点，已确认结算单不允许直接覆盖、变更以调整记录叠加差额；流失预警以到课沉寂度、缺勤倾向、课时余量与到期紧迫等因子评分分档，输出待跟进学员清单。

五、研究方法与验证方案

研究过程采用文档驱动与核心链路优先的方法：先完成需求与设计文档，再按报名退费、排课调课、考勤课时、薪资核算与运营预警等核心链路逐步实现并逐模块联调。验证采用分层测试策略：后端以单元测试覆盖核心纯逻辑，前端以组件测试验证关键组件，随后开展接口验收与浏览器自动化 UI 验收，并针对五类角色分别开展权限验收，最后以容器化方式部署至生产环境完成上线验证。

六、可行性说明

技术可行性方面，所选框架与组件均为成熟开源方案，团队具备相应开发经验，四类关键技术问题均可通过已被工程实践验证的机制实现。经济可行性方面，系统采用开源技术栈与容器化部署，不依赖商业授权，成本可控。操作可行性方面，管理后台面向复杂管理场景、移动端面向高频轻量场景，终端形态与岗位习惯匹配，便于机构人员上手。
